## Reading

With no pushed state anywhere in the cache, forcing the first generated token that the pushed `:` pass chose
reproduces the pushed run token for token on 26 of 28 rows and in every count. The whole effect of the §38
direction, as used in §39, passes through one decision at `:`: the first generated token is not ` unknown`. After
that token the unpushed model continues on its own, and with the evidence cut the same forced token gives the same
17 answers and 2 gold as the pushed cut run. The pre-registered prediction (split or undetermined, gF ≤ 4) was wrong,
for the second time in this pair: the F1 worry of §39, that later tokens keep reading the pushed `:` state, does not
materialise on these rows.

What this does and does not say. It sharpens §39's M1: the answer is available at `:`, and the only thing the push
changes downstream is which token comes out first. It does not say the first token is content-free. On most rows that
token already carries content (` Serenity`, ` Tom`, ` $`, ` 5`): the pushed `:` pass computes the answer's first
token, and the clean model finishes the answer from it. Gold-first makes the same point from the other side: a
content-bearing gold first token gives the model the answer (13 of 28 gold, an upper bound helped by the token), a
generic one (` The`, ` I`, ` `) mostly does not. So "refusal is a one-token decision" is the right record sentence,
with "the token the push chooses is the answer's own first token, not a neutral one" beside it. A fixed neutral token
forced on every row (for example ` The`) would separate "any non-refusal token" from "the push's token"; descriptive,
free, not required for the record.
