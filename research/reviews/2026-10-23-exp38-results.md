## 4. Caveats for §38 and STATE.md

1. **Selection.** The setting that works was chosen on dev labels after the pre-registered ans-only rule picked a
   setting that fails its specificity control. The confirmation folds were sealed throughout and read once; the
   selection is a train-side choice, but it is one more degree of freedom than the pre-registration allowed, and the
   record must say so wherever the result is cited.
2. **Mechanism is narrower than §4's first reading.** The add is applied at the `:` token and at every generated token
   (`add_spec`), so the generated tokens can still attend to the evidence. What is shown: a single content-free direction
   at layer 29 switches off the refusal, after which the 3B extracts the gold from the evidence in view at a rate above
   the instruction line's, and far above its rate without the evidence. Not shown: that the answer was already computed
   at the `:` position. Separating that needs a one-position add (step 0 only), a free laptop variant.
3. **Judge.** Same model as §35, different engine; agreement 0.971 (0.943, 0.994) with the cached verdicts on the same
   rows and 1.000 on identical texts, above the 0.90 bar; no caveat line needed.
4. **Reproduction.** 0.957 on R; the 4 dropped R rows and 1 C row are bf16-vs-vLLM flag differences; nothing read on them.
5. **Attempt 1** died at the smoke on a missing `scipy` import, before any row; 2 minutes of pod time. The stub
   end-to-end test ran in the laptop environment, so it could not see a package missing from the bundle's install line.
   Proposed amendment to the pre-launch rule (D-08/D-22): the stub test runs from the extracted bundle in a fresh
   virtual environment built from the bundle's own install line. For the user to decide.
