Teaching a Small Model to Manage an AI Agent's Memory

Thesis proposal (updated October 2026)

The problem

AI agents built on large language models can only read a limited amount of text at once. In a long task, like a support chat that runs for days, the history soon grows past that limit, so something has to decide what the model keeps, what gets filed away, and what gets thrown out. Most systems use fixed rules like "keep the most recent messages," which are cheap but often throw away the one fact that ends up mattering.

Research questions

Overall: can a very small, separate model learn these memory decisions better than fixed rules, without retraining the language model itself?

  1. RQ1. Under a tight memory budget, can a small learned controller beat fixed memory rules?
  2. RQ2. What is the right way to learn from hindsight, when the controller can't see the future that its teacher sees?
  3. RQ3. Does reinforcement learning (GRPO) add anything beyond imitation, and does it matter how it assigns credit to each decision?
  4. RQ4. Does it hold up with real language models and real long conversations, and when is it worth it over a simple rule?

My approach

I built a test framework where a frozen language model answers questions while a separate "memory controller" decides what to keep, archive, delete or retrieve. The controller is tiny (about 27,000 parameters) and trains on a laptop. Because my tasks are simulated, I know afterwards which facts were needed, and I use that hindsight to build a teacher for the controller to copy, then try reinforcement learning (GRPO) on top.

What is new in this work

  1. A tiny controller kept separate from a frozen language model (RQ1, RQ4). Most recent work retrains the language model itself; here only the small controller learns, so it can sit in front of any model. With Qwen2.5-7B reading, it matches showing the model everything while using 40% of the text.
  2. A "regret" teacher for copying hindsight (RQ2). Copying an all-knowing teacher works badly (34% right at a tight budget), because the student can't see what it sees. Copying a teacher that accepts every choice that costs nothing gets 85%, beating every fixed rule I tested.
  3. Finding that search, not learning, was the bottleneck, and fixing it (RQ1, RQ3). Most remaining mistakes were two-step questions whose second fact never showed up as an option. A simple "follow the clue" search raised accuracy from 85% to 92% (83% to 89% with Qwen2.5-7B), about half the gap to a perfect controller.
  4. Free per-question credit for GRPO (RQ3). The simulator replays exactly, so each decision can be credited for its own question at no extra cost. GRPO adds about one point; the credit method made no difference.

What I will do next

  1. (RQ4) Test on two public benchmarks of long conversations, LoCoMo and LongMemEval. So far simple rules win, because my controller rarely retrieves on real conversations. Next it will always retrieve the top few results and learn only what to keep.
  2. (RQ2) Study memory that costs something to store, where filing everything away is no longer free.
  3. (RQ4) Work out when a small learned controller is worth it, and when a simple rule is enough.

Why it matters

If a small, cheap model can manage memory well, any agent could use it without retraining a large model. If it can't, knowing why still helps anyone building agents that need to remember.

A. Setup

At step \(t\) the memory state is \(s_t = (\mathcal{A}_t, \mathcal{R}_t)\): the active items, whose tokens must fit a budget \(\sum_{i\in\mathcal{A}_t} \ell_i \le B\), and the archive. The budget is a fraction of the whole history, \(B = f \cdot L\) with \(f \in \{2, 5, 10, 25\}\%\). When the active memory is over budget, the controller removes items one at a time, each by an operation \(o \in \{\textsf{evict}, \textsf{archive}\}\), until it fits. When a question arrives, it may retrieve items from a shortlist \(\mathcal{C}_t\) of the archive. The reward is the number of questions answered correctly, minus 0.1 for every forced fallback eviction:

\[ R = \sum_{t} r_t, \qquad r_t = \mathbb{1}[\text{question at } t \text{ answered correctly}] - 0.1\, F_t . \]

B. Policy

A DeepSets scorer gives each candidate item \(i\) (features \(x_i\), plus mean and max pooled summaries of all candidates and global features \(g_t\)) one logit per operation, \(z_{i,o} = f_\theta(x_i, \bar{x}, g_t)\), and a retrieval logit \(z_{i,\text{ret}}\). Removals are a sequence of softmax draws without replacement over the remaining (item, operation) pairs, and retrievals are independent Bernoulli draws:

\[ \pi_\theta(a_t \mid s_t) = \prod_{j\in\mathcal{C}_t} \sigma(z_{j,\text{ret}})^{y_j}\,\big(1-\sigma(z_{j,\text{ret}})\big)^{1-y_j} \; \prod_{k=1}^{K} \frac{\exp z_{(i_k,o_k)}}{\sum_{(i,o)\in M_k} \exp z_{(i,o)}} , \]

where \(M_k\) is the set of pairs still available at the \(k\)-th removal.

C. Hindsight and the two teachers

A reference pass with unlimited memory gives every item's next need \(n_i(t)\): the first later step whose question uses it (\(\infty\) if never). The oracle teacher deletes never-needed items, then archives in order of furthest next need: one action per state. The regret teacher charges each (item, operation) its regret with the oracle playing on, and accepts every action of least regret:

\[ \text{reg}(i,\textsf{evict}) = \mathbb{1}[n_i(t)<\infty], \qquad \text{reg}(i,\textsf{archive}) = c + \rho\,\mathbb{1}[n_i(t)<\infty], \qquad A^*(s_t) = \arg\min_{(i,o)} \text{reg}(i,o), \]

with archive price \(c = 0\) and retrieval risk \(\rho = 0\) here. For a never-needed item both operations then cost 0. The oracle breaks that tie towards deletion, which a learner that cannot see the future cannot imitate, so it learns to delete needed items too. The student is trained by DAgger with a set-valued loss: at each removal along the teacher's sequence, the probability mass the policy puts on the accepted set; for retrieval, a cross-entropy against "needed right now":

\[ \mathcal{L}_{\text{BC}}(\theta) = -\sum_{k} \log \sum_{a\in A^*_k} \pi_\theta(a \mid s, M_k) \; - \sum_{j\in\mathcal{C}_t} \Big[ y^*_j \log \sigma(z_{j,\text{ret}}) + (1-y^*_j)\log\big(1-\sigma(z_{j,\text{ret}})\big) \Big], \quad y^*_j = \mathbb{1}[n_j(t) = t]. \]

D. GRPO

For each training episode (one seed and one budget) the policy samples a group of \(G = 8\) rollouts with returns \(R_1,\dots,R_G\). Every decision in rollout \(g\) gets the same group-standardised advantage, and the policy is updated with PPO's clipped objective and an entropy bonus, with no value network:

\[ \hat{A}_g = \frac{R_g - \mu_G}{\sigma_G + \epsilon}, \qquad \mathcal{J}(\theta) = \mathbb{E}\Big[\min\big(\rho_t \hat{A}_g,\; \text{clip}(\rho_t, 1-\varepsilon, 1+\varepsilon)\,\hat{A}_g\big)\Big] + \beta\, \mathcal{H}(\pi_\theta), \quad \rho_t = \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_\text{old}}(a_t\mid s_t)}, \]

with \(\varepsilon = 0.2\), \(\beta = 0.01\), 4 epochs per batch, and \(\hat{A}_g = 0\) when the group is tied.

E. Modifications of GRPO tested

  1. Batch scale, per budget (after Dr. GRPO and Lite PPO). Centre within the group, but scale by the spread of the whole batch within the same budget stratum \(k\), so nearly tied groups are not blown up to \(\pm 1\):
    \[ \hat{A}_g = \frac{R_g - \mu_G}{\sigma_{B,k} + \epsilon}, \qquad \sigma_{B,k}^2 = \frac{1}{|B_k|}\sum_{g\in B_k} (R_g - \mu_{G(g)})^2 . \]
  2. Best-of-\(G\) imitation (RAFT), a filtered-imitation baseline: \(\hat{A}_g = \mathbb{1}\big[R_g = \max_{g'} R_{g'} \text{ and unique}\big]\).
  3. Per-question credit. All \(G\) rollouts of a group replay the same seed, so they meet the same question at the same step \(t\). A decision at \(t\) also gets its rollout's reward at \(t\) relative to the group's mean reward at \(t\), at no extra cost:
    \[ \hat{A}_{g,t} = \hat{A}_g + \omega \big( r^{(g)}_t - \bar{r}_t \big), \qquad \bar{r}_t = \frac{1}{G}\sum_{g'} r^{(g')}_t, \quad \omega = 1 . \]
  4. Expert kept in the loss (after CHORD and SRFT): \(\mathcal{L} = -\mathcal{J}(\theta) + \lambda\, \mathcal{L}_{\text{BC}}(\theta)\) with \(\lambda = 0.5\), the regret teacher labelling the learner's own states.

F. The follow-the-clue search

The controller can only retrieve from a shortlist: the top 8 archive items for the question \(q\) by BM25. In a two-hop question the second fact names an entity the question never mentions, so it is rarely on that list (Figure 3). The search adds a second pass. Let \(W(x)\) be the content words of \(x\) and \(\text{df}(w)\) the number of memory items containing \(w\).

  1. Anchor: the question's rarest word in memory, \(w^* = \arg\min_{w\in W(q),\, \text{df}(w)>0} \text{df}(w)\) (what the question names).
  2. Seeds: the best BM25 matches to \(q\) in active memory or the archive that contain \(w^*\) and add new words; the first \(m = 2\) are used.
  3. For each seed \(s\), a second query: the question's words the seed lacks, plus the seed's \(c = 3\) rarest new words (the bridge entity):
    \[ q'(s) = \big(W(q)\setminus W(s)\big) \;\cup\; \text{rarest}_c\big(W(s)\setminus W(q)\big) . \]
  4. The top \(k = 4\) archive items by \(\max_s \text{BM25}(q'(s), \cdot)\) join the shortlist, with a feature marking them.
