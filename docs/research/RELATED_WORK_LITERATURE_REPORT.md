# Related work crowds the learned-controller niche

**Every component of the project already exists somewhere in the literature, but no published system combines them, so the novelty risk is combinational rather than component-level.** The closest neighbours are all from 2026: LRE trains a kilobyte-scale, language-model-free keep/evict scorer from hindsight self-labels under a strict 2048-token budget and evaluates on AppWorld plus LoCoMo ([arXiv](https://arxiv.org/html/2606.20954)); MemCon runs a tabular bandit over Retrieve/Consolidate/Forget/NoOp for a frozen task LLM on ALFWorld, PDDL and ScienceWorld ([arXiv](https://arxiv.org/html/2607.13591)); Memex(RL) states the project's own archive principle ("keep the active reasoning state small, but do not throw evidence away") but trains a 30B task model rather than a separate controller ([arXiv](https://arxiv.org/html/2603.04257v1)); EMBER reports an oracle-retention upper bound under a fixed evidence budget ([arXiv](https://arxiv.org/html/2606.05894)); and the restore-counterfactual audit splits failures into irreversible (evicted) versus recoverable (retrieval miss), finding irreversibility reaches 1.00 for every policy at an 8k-token budget ([arXiv](https://arxiv.org/abs/2609.08279)). The training recipe (hindsight Belady oracle, on-policy DAgger, then RL refinement) is a decade old in cache replacement (Parrot, ICML 2020, [PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)) and was ported to KV eviction by ForesightKV (ICML 2026, [arXiv](https://arxiv.org/abs/2602.03203)). What the sweep did not find is any paper that (a) trains a separate sub-million-parameter neural policy with PPO over a keep/evict/archive/retrieve/compact/consolidate action set under a hard active budget, (b) reports a seven-way failure attribution, or (c) states that imitating a hindsight deletion oracle is the wrong target once an archive exists; the last point is implied piecemeal by Demand-MIN ([ACM](https://dl.acm.org/doi/10.1109/ISCA.2018.00020)), MemAudit ([arXiv](https://arxiv.org/html/2605.02199)) and MemAct's own limitations ([arXiv](https://arxiv.org/html/2510.12635)) but not stated. The project's observation that the hindsight oracle is blind after the trajectory diverges is the memory-control form of a fact the caching literature relies on implicitly: Parrot can compute Belady at any visited state only because the access stream "is independent of the action" ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)), and Memory-R2 names the agent case where "memory turns the agent's past actions into part of its future environment" ([arXiv](https://arxiv.org/abs/2605.21768)). All venues and numbers below were checked against a primary page by the researchers on 2026-09-30 unless flagged "(venue unverified)"; items that could not be located are listed at the end so they are not cited.

## The field's default controller is the task LLM prompted with a memory API

The architectural lineage that the project's action vocabulary descends from is MemGPT, and it is worth being precise about what MemGPT does and does not decide. Packer et al. cast context management as OS-style virtual memory: a main context of system instructions, working context and a FIFO queue, plus external recall and archival storage, with the LLM calling `core_memory_append`, `core_memory_replace`, `archival_memory_insert`, `archival_memory_search` and `conversation_search` ([arXiv PDF](https://arxiv.org/pdf/2310.08560)). **Eviction is not one of those calls**: a queue manager emits a memory-pressure warning at a token threshold and, at a flush threshold, evicts FIFO messages into a recursive summary while keeping them searchable in recall storage ([arXiv PDF](https://arxiv.org/pdf/2310.08560)). So MemGPT has an explicit token budget and an archive-and-retrieve path, but the removal decision is a fixed FIFO rule and the retrieval decision is made by the same LLM that does the task. Its four benchmarks (deep memory retrieval, conversation opener, multi-document QA, nested key-value retrieval) are all retrieval over a fixed history ([arXiv PDF](https://arxiv.org/pdf/2310.08560)). The record for MemGPT is therefore: **Citation** Charles Packer, Sarah Wooders, Kevin Lin, Vivian Fang, Shishir G. Patil, Ion Stoica, Joseph E. Gonzalez, "MemGPT: Towards LLMs as Operating Systems," arXiv 2310.08560, 2023/2024, [URL](https://arxiv.org/abs/2310.08560). **Problem** fixed context windows in extended conversation and document analysis. **Method** tiered context with LLM-callable paging functions and interrupts. **Action space** append/replace core memory, insert/search archival, search recall; automatic FIFO flush with recursive summary. **Training signal** none (prompted). **Benchmarks** DMR, conversation opener, multi-doc QA, nested KV. **Solves** the appearance of unbounded context under a bounded window. **Leaves open** a learned or deliberate eviction decision; sequential-task evaluation; any oracle comparison. **How the project differs** the project replaces the FIFO flush with a learned seven-way choice made by a separate 27k-parameter policy that never reads text, evaluates that choice against an ILP oracle and heuristics at equal budget, and adds a sequential task where a wrong eviction forces a job restart; MemGPT's FIFO-with-summary is essentially the project's FIFO+COMPACT baseline.

The external-store family never faces an eviction decision at all, because the active context is filled by top-k retrieval from an unbounded store. **A-MEM** (Wujiang Xu, Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang, "A-MEM: Agentic Memory for LLM Agents," NeurIPS 2025 as listed on arXiv, arXiv 2502.12110, [URL](https://arxiv.org/abs/2502.12110)) addresses "fixed operations and structures" with Zettelkasten-style note construction, link generation, memory evolution and retrieval; no deletion primitive is stated, no training, no budget, conversational QA only ([arXiv](https://arxiv.org/abs/2502.12110)). **Mem0** (Prateek Chhikara, Dev Khant, Saket Aryan, Taranjeet Singh, Deshraj Yadav, "Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory," arXiv 2504.19413, 2025, [URL](https://arxiv.org/abs/2504.19413)) extracts, consolidates and retrieves salient facts, reports a 26% relative LLM-judge gain over OpenAI memory on LoCoMo with 91% lower p95 latency and over 90% token savings, but those savings are an outcome, not a constraint ([arXiv](https://arxiv.org/abs/2504.19413)); the ADD/UPDATE/DELETE/NOOP labels usually attributed to Mem0 were not verified from its abstract by the researchers and should be cited from the paper body if used. **Zep** (Preston Rasmussen, Pavlo Paliychuk, Travis Beauvais, Jack Ryan, Daniel Chalef, "Zep: A Temporal Knowledge Graph Architecture for Agent Memory," arXiv 2501.13956, 2025, [URL](https://arxiv.org/abs/2501.13956)) uses the Graphiti bi-temporal graph; superseded edges are invalidated with validity intervals rather than deleted; DMR 94.8% vs MemGPT 93.4% and up to +18.5% on LongMemEval ([arXiv](https://arxiv.org/abs/2501.13956)). **HippoRAG** (Bernal Jiménez Gutiérrez, Yiheng Shu, Yu Gu, Michihiro Yasunaga, Yu Su, NeurIPS 2024, arXiv 2405.14831, [URL](https://arxiv.org/abs/2405.14831)) is index-and-retrieve with Personalized PageRank, 10–30x cheaper than iterative retrieval on multi-hop QA ([arXiv](https://arxiv.org/abs/2405.14831)). **Hindsight** (Chris Latimer et al., "Hindsight is 20/20: Building Agent Memory that Retains, Recalls, and Reflects," arXiv 2512.12818, 2025, [URL](https://arxiv.org/abs/2512.12818)) has retain/recall/reflect over four networks, LongMemEval 91.4% and LoCoMo 89.61% ([arXiv](https://arxiv.org/abs/2512.12818)); despite the title it is prompted and has nothing to do with hindsight oracles, which matters for a reader scanning the bibliography. **ECHO** (Yu Qian et al., "ECHO: A Cognitively Inspired, Auditable Memory Plane for Long-Horizon Agents," arXiv 2608.21755, 2026, [URL](https://arxiv.org/abs/2608.21755)) reports LoCoMo Hit@10 of 96.29% but also an unusually candid self-audit: on a 91-question sample Mem0 OSS scored 64.84% against ECHO's 41.76%, and "source-specific phrases in the query-expansion rules" mean its retrieval numbers are "not independent confirmation" ([arXiv](https://arxiv.org/abs/2608.21755)). For all six the fields collapse to the same answers: **action space** write/link/update/retrieve with no eviction; **training** none; **budget** none; **benchmarks** LoCoMo, LongMemEval, DMR or multi-hop QA; **oracle and attribution** none; **sequential eval** none. **How the project differs** from the whole family: the project's budget is a hard constraint on the active context and its store-side actions (MOVE_TO_ARCHIVE, RETRIEVE_FROM_ARCHIVE) are chosen per item by a learned policy, so it measures the retention decision these systems never make. The project's finding that archive plus retrieval lifts FIFO from 0.23 to 0.73 at a 5% budget and then the retriever becomes the bottleneck is the quantity these systems implicitly assume away by retrieving from everything.

Three older systems supply the heuristics the project benchmarks against. **Generative Agents** (Joon Sung Park, Joseph C. O'Brien, Carrie J. Cai, Meredith Ringel Morris, Percy Liang, Michael S. Bernstein, arXiv 2304.03442, 2023, UIST 2023 venue unverified, [URL](https://arxiv.org/abs/2304.03442)) scores retrieval by recency, importance and relevance and reflects into higher-level memories, with no deletion and no budget; evaluation is believability in a 25-agent sandbox ([arXiv](https://arxiv.org/abs/2304.03442)). This is the source of the project's age-decay, similarity and salience heuristics. **MemoryBank** (Wanjun Zhong, Lianghong Guo, Qiqi Gao, He Ye, Yanlin Wang, arXiv 2305.10250, 2023, AAAI 2024 venue unverified, [URL](https://arxiv.org/abs/2305.10250)) is one of the few non-RL systems with an explicit forgetting rule, an Ebbinghaus-curve update that lets the agent "forget and reinforce memory based on time elapsed and the relative significance" ([arXiv](https://arxiv.org/abs/2305.10250)); it has deletion but no archive-then-retrieve, and its evaluation is a companion chatbot without a standard benchmark. LRE later uses "MemoryBank decay" as a named baseline ([arXiv](https://arxiv.org/html/2606.20954)). **Reflexion** (Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao, arXiv 2303.11366, 2023, NeurIPS 2023 venue unverified, [URL](https://arxiv.org/abs/2303.11366)) writes verbal reflections into an episodic buffer across trials on ALFWorld, HotPotQA and HumanEval ([arXiv](https://arxiv.org/abs/2303.11366)); it is trial-and-retry, not within-episode context management, so it is peripheral. **How the project differs** from all three: the project treats their scoring rules as fixed baselines, and its finding that heuristic ranking flips between the recall and sequential tasks is direct evidence that no single hand-coded score of this kind is task-general.

The compaction family is where the project's COMPACT and CONSOLIDATE actions have precedent, and also where the literature has named the failure modes the project's `compression_lost_detail` and `consolidation_incorrect` labels measure. **ACE** (Qizheng Zhang et al., "Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models," ICLR 2026 as listed on arXiv, arXiv 2510.04618, [URL](https://arxiv.org/abs/2510.04618)) names "brevity bias, which drops domain insights for concise summaries," and "context collapse, where iterative rewriting erodes details," and answers with incremental delta updates by generator/reflector/curator roles, evaluated on AppWorld, FiNER and Formula ([arXiv](https://arxiv.org/abs/2510.04618)); no weights are trained, there is no budget, no archive and no eviction primitive, but AppWorld is a genuine long-horizon task. **LLMLingua** (Huiqiang Jiang, Qianhui Wu, Chin-Yew Lin, Yuqing Yang, Lili Qiu, EMNLP 2023, arXiv 2310.05736, [URL](https://arxiv.org/abs/2310.05736)) is irreversible COMPACT only, with a separate small compressor and an explicit "budget controller" giving up to 20x compression on GSM8K, BBH, ShareGPT ([arXiv](https://arxiv.org/abs/2310.05736)). **Sculptor** (Mo Li, L.H. Xu, Qitai Tan, Long Ma, Ting Cao, Yunxin Liu, arXiv 2508.04664, 2025, [URL](https://arxiv.org/abs/2508.04664)) is training-free but exposes summary / hide / restore tools, which is an archive-and-retrieve primitive with no learned policy ([arXiv](https://arxiv.org/abs/2508.04664)). **RecurrentGPT** (Wangchunshu Zhou et al., arXiv 2305.13304, 2023, [URL](https://arxiv.org/abs/2305.13304)) rewrites a fixed prompt-resident short-term memory and appends disk-resident long-term summaries with embedding retrieval, for long-text generation only ([arXiv](https://arxiv.org/abs/2305.13304)). **Sleep-time compute** (Kevin Lin, Charlie Snell, Yu Wang, Charles Packer, Sarah Wooders, Ion Stoica, Joseph E. Gonzalez, arXiv 2504.13171, 2025, [URL](https://arxiv.org/abs/2504.13171)) consolidates offline before queries arrive, cutting test-time compute about 5x at equal accuracy on Stateful GSM-Symbolic, with the stated caveat that benefit depends on query predictability ([arXiv](https://arxiv.org/abs/2504.13171)). **How the project differs**: ACE avoids lossy rewriting rather than choosing when to accept it, LLMLingua compacts without an archive, Sculptor archives without learning; the project makes COMPACT, COMPACT_AND_ARCHIVE and CONSOLIDATE learned alternatives to EVICT and attributes each failure to the one that caused it, which none of the four reports. ACE's context-collapse observation is the closest published statement of why the project's oracle should not reward repeated compaction.

Two 2026 surveys frame the whole family and are safe to cite for the open-problem statements. Pengfei Du's "Memory for Autonomous LLM Agents: Mechanisms, Evaluation, and Emerging Frontiers" (arXiv 2603.07670, 2026, [URL](https://arxiv.org/abs/2603.07670)) formalises a write–manage–read loop, distinguishes heuristic, prompted self-control and learned control paradigms with AgeMem as the primary RL example, and lists among open challenges estimating memory importance "without future information," "learning to forget," and a task-agnostic "foundation model for memory control" ([arXiv HTML](https://arxiv.org/html/2603.07670v1)); it also states that consolidation "typically requires either explicit developer rules or periodic LLM-driven summarization, both of which are fragile and hard to validate" ([arXiv HTML](https://arxiv.org/html/2603.07670v1)). "Memory in the Age of AI Agents: A Survey" (Yuyang Hu et al., 47 authors, arXiv 2512.13564, [URL](https://arxiv.org/abs/2512.13564)) names memory automation and RL integration as frontiers ([arXiv](https://arxiv.org/abs/2512.13564)). "Anatomy of Agentic Memory" (Dongming Jiang et al., arXiv 2602.19320, 2026, [URL](https://arxiv.org/abs/2602.19320)) finds "existing benchmarks are often underscaled, evaluation metrics are misaligned with semantic utility, performance varies significantly across backbone models, and system-level costs are frequently overlooked" ([arXiv](https://arxiv.org/abs/2602.19320)). The Zhang et al. 2024 survey (arXiv 2404.13501, [URL](https://arxiv.org/abs/2404.13501)) is the standard earlier reference.

## The 2025 RL wave fine-tunes the task model on outcome-only reward

Every 2025 RL system trains the LLM that performs the task, broadcasts a terminal reward to all memory decisions, and evaluates on QA after a history; the project's separation of a frozen task model from a tiny controller is the structural difference that recurs in every record below.

**Memory-R1.** Sikuan Yan, Xiufeng Yang, Zuchao Huang, Ercong Nie, Zifeng Ding, Zonggen Li, Xiaowen Ma, Jinhe Bi, Kristian Kersting, Jeff Z. Pan, Hinrich Schütze, Volker Tresp, Yunpu Ma, "Memory-R1: Enhancing Large Language Model Agents to Manage and Utilize Memories via Reinforcement Learning," ACL 2026 long paper, arXiv 2508.19828, [arXiv](https://arxiv.org/abs/2508.19828), [ACL Anthology](https://aclanthology.org/2026.acl-long.583/). **Problem** memory pipelines are "static and heuristic-driven, lacking a learned mechanism for deciding what to store, update, or retrieve" ([arXiv](https://arxiv.org/abs/2508.19828)). **Method** a Memory Manager LLM and an Answer Agent LLM, both fine-tuned (LLaMA-3.1-8B, Qwen2.5-7B). **Action space** ADD / UPDATE / DELETE / NOOP on a memory bank; the answer agent retrieves 60 candidates and distils them ([arXiv HTML](https://arxiv.org/html/2508.19828v2)). **Training signal** PPO and GRPO with outcome-only reward, exact match of the downstream answer, from 152 QA pairs of one LoCoMo dialogue ([arXiv HTML](https://arxiv.org/html/2508.19828v2)). **Benchmarks** LoCoMo, MSC, LongMemEval; LoCoMo F1 30.41 to 45.02 over Mem0 ([arXiv HTML](https://arxiv.org/html/2508.19828v2)). **Solves** learned write-side management with almost no labels. **Leaves open** no budget, no oracle, no sequential task, no limitations section found. **Differs** the project's controller is 27k parameters, not an 8B LLM; it has no ADD/UPDATE (items arrive from the environment) but has ARCHIVE and RETRIEVE; it is trained under a hard budget and evaluated against an exact ILP oracle; and its DELETE-equivalent (EVICT) is measured for what it destroys.

**MemAct.** Yuxiang Zhang, Jiangming Shu, Ye Ma, Xueyuan Lin, Shangxi Wu, Jitao Sang, "Memory as Action: Autonomous Context Curation for Long-Horizon Agentic Tasks," arXiv 2510.12635, 2025 (OpenReview submission exists; venue/decision unverified), [arXiv](https://arxiv.org/abs/2510.12635), [OpenReview](https://openreview.net/forum?id=ddGsiaISXg). **Problem** context curation for long-horizon agents as part of the action space. **Method** a Prune&Write operator where each memory action names historical turn IDs to delete and inserts generated content in their place; Dynamic Context Policy Optimization segments the "fractured" trajectory at each edit and applies GRPO per segment because deletions break the monotonic-prefix assumption ([arXiv HTML](https://arxiv.org/html/2510.12635)). **Action space** delete-set plus write; no archive. **Training signal** sparse terminal reward, +1.0 success, −0.1 for exceeding 20K tokens or 40 steps ([arXiv HTML](https://arxiv.org/html/2510.12635)). **Benchmarks** 2WikiMultihopQA, HotpotQA, Bamboogle, Frames, BrowseComp-Plus and a multi-objective QA set; the 14B model reaches 59.1% vs Qwen3-235B 53.1% with 49% shorter context ([arXiv HTML](https://arxiv.org/html/2510.12635)). **Solves** RL under context edits; shows a fixed every-5-turns pruning baseline underperforms learned pruning ([arXiv HTML](https://arxiv.org/html/2510.12635)). **Leaves open** by its own account: sparse-reward credit assignment, the "risk of information deletion becoming relevant later," lossy summarization, and future "selective retrieval from external storage and tiered caching" ([arXiv HTML](https://arxiv.org/html/2510.12635)). **Differs** MemAct's stated future work is the project's present design (a tiered archive with retrieval, separate from the task model); the project also measures the deletion-becomes-relevant risk directly as the `evicted` and `archived_not_retrieved` attribution classes. MemAct's 20K hard limit is the closest 2025 analogue of the project's hard budget, but it is a penalty on the task model rather than a constraint on a controller.

**AgeMem.** Yi Yu, Liuyi Yao, Yuexiang Xie, Qingquan Tan, Jiaqi Feng, Yaliang Li, Libing Wu, "Agentic Memory: Learning Unified Long-Term and Short-Term Memory Management for Large Language Model Agents," ACL 2026 (SAC Highlight), arXiv 2601.01885, [arXiv](https://arxiv.org/abs/2601.01885), [ACL Anthology PDF](https://aclanthology.org/2026.acl-long.981.pdf). **Problem** prior systems handle LTM and STM separately "relying on heuristics or auxiliary controllers, which limits adaptability and end-to-end optimization" ([arXiv](https://arxiv.org/abs/2601.01885)). **Method** memory operations as tool actions of the task LLM (Qwen2.5-7B, Qwen3-4B). **Action space** six tools: LTM Add/Update/Delete, STM Retrieve/Summary/Filter ([arXiv HTML](https://arxiv.org/html/2601.01885)), the most complete published set. **Training signal** three-stage progressive RL with step-wise GRPO broadcasting the terminal reward to all memory decisions ([arXiv HTML](https://arxiv.org/html/2601.01885)). **Benchmarks** ALFWorld, SciWorld, PDDL, BabyAI, HotpotQA; Qwen2.5-7B average 41.96%, +4.8–8.6 points over LangMem/A-Mem/Mem0, tokens down 3–5% ([arXiv HTML](https://arxiv.org/html/2601.01885)). **Solves** unified STM+LTM control on interactive tasks. **Leaves open** no explicit hard budget, no oracle, no attribution. **Differs** AgeMem's motivation is an argument *against* the project's design ("auxiliary controllers" limit end-to-end optimisation), which the project must answer empirically; AgeMem's action set overlaps the project's most closely of any RL paper (Delete≈EVICT, Summary≈COMPACT, Retrieve≈RETRIEVE_FROM_ARCHIVE), but the controller is the 7B task model, there is no hindsight oracle, and the budget is soft. Four of its five benchmarks are sequential, which is stronger than most of the field.

**Memex(RL).** Zhenting Wang, Huancheng Chen, Jiayun Wang, Wei Wei, "Memex(RL): Scaling Long-Horizon LLM Agents via Indexed Experience Memory," arXiv 2603.04257, 2026, [arXiv HTML](https://arxiv.org/html/2603.04257v1). **Problem** long-horizon agents that either overflow context or discard evidence. **Method** a compact in-context indexed summary paired with a full-fidelity external archive under stable indices; the 30B task model learns CompressExperience (summarise and archive) and ReadExperience (dereference an index to re-inject exact evidence), with compression timing learned via a context-status "soft trigger" ([arXiv HTML](https://arxiv.org/html/2603.04257v1)). **Action space** archive-with-summary and retrieve-exact; no plain evict. **Training signal** GRPO with shaped return R = R_task − P_context − P_redundancy − P_format, overflow penalised above an 8K working-token threshold, segments split at compression boundaries sharing the terminal reward ([arXiv HTML](https://arxiv.org/html/2603.04257v1)). **Benchmarks** a modified ALFWorld with hidden admissible commands where object and location IDs must be recovered from memory; success 24.22% to 85.61%, peak working context down 43%, read calls rising from 1 to 6–7 per episode ([arXiv HTML](https://arxiv.org/html/2603.04257v1)). **Solves** evidence-preserving compression on a sequential task with a theoretical optimality proposition under a decision-sufficiency assumption. **Leaves open** by its own account that assumption is unvalidated, one environment, unclear horizon scaling ([arXiv HTML](https://arxiv.org/html/2603.04257v1)). **Differs** Memex(RL) is the nearest neighbour on the archive-rather-delete axis and its modified ALFWorld is the closest published analogue of the project's sequential workflow task, but the controller is the task model, the budget is a soft penalty, there is no hindsight oracle, no heuristic sweep, and no attribution. The project's finding that after archiving the retriever becomes the bottleneck corresponds to Memex's observed rise in read calls, which Memex reports but does not decompose.

**MEM1.** Zijian Zhou, Ao Qu, Zhaoxuan Wu, Sunghwan Kim, Alok Prakash, Daniela Rus, Jinhua Zhao, Bryan Kian Hsiang Low, Paul Pu Liang, "MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents," ICLR 2026, arXiv 2506.15841, [arXiv](https://arxiv.org/abs/2506.15841), [ICLR](https://iclr.cc/virtual/2026/poster/10008961). **Method** the agent rewrites an internal-state block each turn and discards all prior tool outputs; a 2D attention mask keeps policy gradients correct under pruning ([arXiv HTML](https://arxiv.org/html/2506.15841v2)). **Action space** overwrite-state (implicit evict-all). **Training signal** PPO, EM on the final answer only; a format reward "degrades final performance"; constant memory is emergent ([arXiv HTML](https://arxiv.org/html/2506.15841v2)). **Benchmarks** 16-objective multi-hop QA (3.5x performance, 3.7x less memory vs Qwen2.5-14B) and WebShop ([arXiv HTML](https://arxiv.org/html/2506.15841v2)). **Leaves open** assumes "well-defined and verifiable rewards." **Differs** MEM1 has no item-level actions and no archive; the project keeps items addressable and chooses per item. MEM1 is the closest precedent for the project's PPO arm in the memory space, but it trains the 7B task model.

**MemAgent (ByteDance/Tsinghua).** Hongli Yu et al., "MemAgent: Reshaping Long-Context LLM with Multi-Conv RL-based Memory Agent," ICLR 2026 Oral, arXiv 2507.02259, [arXiv](https://arxiv.org/abs/2507.02259). A fixed 1,024-token memory overwritten after each 5,000-token chunk, trained with Multi-Conv DAPO under a rule-based verifier applied uniformly to all memory updates; extrapolates from 8K training to 3.5M tokens ([arXiv HTML](https://arxiv.org/html/2507.02259v2)). The extrapolation loss is reported as "<5%" in one extraction and "<10%" in another, so quote the primary text. **Differs** explicit budget by construction, but document QA only, no item-level choice, no archive, task model trained.

**ReSum.** Xixi Wu et al. (Tongyi Lab), "ReSum: Unlocking Long-Horizon Search Intelligence via Context Summarization," arXiv 2509.13313, 2025, [arXiv](https://arxiv.org/abs/2509.13313). A rule-triggered external summariser (ReSumTool-30B, distilled from GPT-OSS-120B) compresses the dialogue; the web agent is trained with ReSum-GRPO broadcasting a trajectory-level reward across segments; +4.5% over ReAct training-free and a further 8.2% with GRPO ([arXiv HTML](https://arxiv.org/html/2509.13313)). Stated open problem: move "from rule-based external summarization toward autonomous, agent-driven mechanisms while maintaining long-range dependency preservation" ([arXiv HTML](https://arxiv.org/html/2509.13313)). **Differs** the trigger is a rule and the summariser is not RL-trained; the project learns *when* to COMPACT as one of seven actions.

**Mem-α.** Yu Wang, Ryuichi Takanobu, Zhiqi Liang, Yuzhen Mao, Yuanzhe Hu, Julian McAuley, Xiaojian Wu, "Mem-α: Learning Memory Construction via Reinforcement Learning," arXiv 2509.25911, 2025, ICLR 2026 per OpenReview listing (page behind a verification wall, venue unverified), [arXiv](https://arxiv.org/abs/2509.25911). Core/episodic/semantic tiers with memory_insert/update/delete tools, GRPO with shaped reward r1 QA + r2 format + β·r3 compression + γ·r4 LM-validated operations; MemoryAgentBench 0.592 vs RAG-Top2 0.502, generalising to 400k tokens ([arXiv HTML](https://arxiv.org/html/2509.25911)). **Differs** soft compression reward rather than hard budget; QA only; task model trained; no oracle.

**Context-Folding and its successors.** Weiwei Sun et al., "Scaling Long-Horizon LLM Agent via Context-Folding," ICML 2026, arXiv 2510.11967, [arXiv](https://arxiv.org/abs/2510.11967): branch into a sub-trajectory then fold it to a summary, trained with FoldGRPO dense process rewards including an Unfolded Token Penalty and an overflow penalty; main trajectory about 8K tokens while processing over 100K on BrowseComp-Plus and SWE-Bench Verified ([arXiv](https://arxiv.org/abs/2510.11967)). FoldAct (arXiv 2512.22733, [URL](https://arxiv.org/abs/2512.22733)), AgentFold (SFT only, arXiv 2510.24699, [URL](https://arxiv.org/abs/2510.24699)), CompactionRL (Yujiang Li et al., arXiv 2607.05378, [URL](https://arxiv.org/abs/2607.05378), SWE-bench Verified 66.8%, +7.0) and ContextPilot (Zhuoshi Pan et al., EMNLP 2026 main, arXiv 2608.28476, [URL](https://arxiv.org/abs/2608.28476), with "soft context offloading" tools and branch sampling at critical edit decisions) extend the recipe. **Differs** all train the task model and fold by sub-task structure rather than per item; ContextPilot's soft offloading is an archive primitive but without a separate controller or oracle.

**Hindsight-credit RL for memory writes.** Four 2026 papers introduce hindsight or counterfactual signals inside RL on the task model; none uses a hindsight oracle as an imitation target. **HiMPO** (Jiangze Yan et al., "HiMPO: Hindsight-Informed Memory Policy Optimization for Less-Entangled Credit in Long-Horizon Agents," arXiv 2606.16285, [URL](https://arxiv.org/html/2606.16285)) computes for each write a local counterfactual utility (answerability with versus without the write) and a hindsight relevance (write likelihood conditioned on the oracle answer), passes credit only when the two agree in sign, and validates with interventions (faithful-under-bad-tool ratio 0.42 vs 1.00 for the baseline); its stated limits are a fixed write schedule and QA/search only ([arXiv HTML](https://arxiv.org/html/2606.16285)). **Mem-T** (Yanwei Yue, Boci Peng, Xuanbo Fan, Jiaxin Guo, Qiankun Li, Yan Zhang, "Mem-T: Densifying Rewards for Long-Horizon Memory Agents," arXiv 2601.23014, [URL](https://arxiv.org/abs/2601.23014)) has formation, evolution (ADD/UPDATE/DELETE/IGNORE) and retrieval actions, MoT-GRPO over memory-operation trees with hindsight credit gated by evidence alignment, and trains formation/evolution "via supervised learning on hindsight-scored demonstrations"; LoCoMo 58.65 F1; it requires ground-truth evidence annotations ([arXiv HTML](https://arxiv.org/html/2601.23014)). **Memory-R2** (Sikuan Yan et al., "Memory-R2: Fair Credit Assignment for Long-Horizon Memory-Augmented LLM Agents," arXiv 2605.21768, [URL](https://arxiv.org/abs/2605.21768)) observes that "memory turns the agent's past actions into part of its future environment" and uses local re-rollouts from shared intermediate memory checkpoints; LoCoMo F1 43.14 to 50.60 over Memory-R1 ([arXiv HTML](https://arxiv.org/html/2605.21768)). **UMA** (Kehao Zhang et al., "Learning to Remember: End-to-End Training of Memory Agents for Long-Context Reasoning," EMNLP 2026, arXiv 2602.18493, [URL](https://arxiv.org/abs/2602.18493)) supervises CRUD maintenance by the mean reward of QA trajectories branching from each memory state under a 16k budget. MemBuilder (arXiv 2601.05488, [URL](https://arxiv.org/html/2601.05488v1)) and TreeMem (arXiv 2605.04811, [URL](https://arxiv.org/html/2605.04811v1)) add per-session synthetic QA rewards and tree-structured multi-agent credit. **Differs** across the group: they compute hindsight *credit* for RL updates of an LLM writer, whereas the project uses a hindsight *policy* as a DAgger teacher for a non-LLM controller and then PPO. Mem-T's supervised learning on hindsight-scored demonstrations is the closest thing to imitation of hindsight in this space and should be named as such. Memory-R2's observation is the published form of the project's "oracle blind after divergence" finding, and its local re-rollout construction is the remedy the project has not yet applied.

## Separate lightweight controllers over frozen task models arrive in 2026

This is the family the project belongs to, and the family the novelty argument must be made against. Among separate controllers only MemCon and LRE are small in the project's sense; AdaCoM, EMBER, MemSifter and Memory-PRM use 4B–14B LLMs as controllers, and no paper in the sweep trains a separate controller with PPO specifically.

**LRE (Learned Relevance Eviction).** Nusrat Jahan Lia, Aritra Mazumder, "Learning What Not to Forget: Long-Horizon Agent Memory from a Few Kilobytes of Learning," arXiv 2606.20954, v1 June 2026, revised September 2026, [arXiv](https://arxiv.org/abs/2606.20954), [HTML](https://arxiv.org/html/2606.20954). **Problem** "when an eviction policy drops a task-critical detail, for example an access token issued at login or a path the next call needs, the action fails" ([arXiv](https://arxiv.org/abs/2606.20954)). **Method** a kilobyte-scale, CPU-only logistic-regression scorer over causal features assigns keep-probabilities; units are ranked by score-per-token and kept greedily within budget by verbatim extraction, with "no neural forward pass and no language-model call at compression time" ([arXiv HTML](https://arxiv.org/html/2606.20954)). **Action space** keep/evict only; evicted units are gone; nothing is summarised. **Training signal** supervised, or hindsight self-labels from the system's own logs: an agent unit is positive if an identifier it introduces is reused by at least three later steps, a conversation turn if it overlaps at least 40% with the eventual answer; self-labels recover 95% of supervised effectiveness ([arXiv HTML](https://arxiv.org/html/2606.20954)). **Benchmarks** AppWorld agents under a strict 2048-token evictable budget (41.1% vs 44.0% keep-everything, zero compressor calls, 52% cut in worst-case peak prompt, 14 tasks no other policy solves) and LoCoMo/LongMemEvalS (0.708 with 68% fewer tokens); baselines FIFO, ACON, MemoryBank decay, dense encoders ([arXiv](https://arxiv.org/abs/2606.20954); [HTML](https://arxiv.org/html/2606.20954)). **Solves** budgeted, deployable eviction with a tiny model; the framing "an eviction policy runs at write time and must decide what to keep before the query or action that needs it exists, unlike a retriever which runs at query time" ([arXiv HTML](https://arxiv.org/html/2606.20954)) is the cleanest published statement of why the project's controller is a control problem. Its case study shows abstractive compression paraphrasing identifiers into unusability and causing loops ([arXiv HTML](https://arxiv.org/html/2606.20954)), which is the project's `compression_lost_detail` class. **Leaves open** no archive, so nothing evicted can come back; keep-everything is the only reference, not a hindsight-optimal placement; no attribution beyond the case study. **Differs** LRE is the single closest system: tiny, language-model-free, feature-based, budgeted, hindsight-labelled, evaluated on both an agent task and LoCoMo. The project adds five actions LRE does not have (archive, retrieve, compact, compact-and-archive, consolidate), replaces a per-item logistic score with a DeepSets policy over the whole set, trains by DAgger against an oracle and by PPO, compares to an exact ILP oracle, and attributes failures. The project's claim to a distinct contribution rests on the archive-and-retrieve axis and the oracle/attribution apparatus, not on the "small learned scorer" idea, which LRE owns.

**MemCon.** Eric Hanchen Jiang et al., "Memory as a Controlled Process: Learned Adaptive Memory Management for LLM Agents," arXiv 2607.13591, 2026, [arXiv](https://arxiv.org/abs/2607.13591), [HTML](https://arxiv.org/html/2607.13591). **Problem** memory operations as an MDP rather than fixed pipeline stages. **Method** a tabular UCB contextual bandit over a discretised state, "millisecond-scale table lookup, not a second LLM invocation," with frozen task LLMs (GPT-4.1-mini, Claude Sonnet-4, DeepSeek-V3.2) and warm-start priors ([arXiv HTML](https://arxiv.org/html/2607.13591)). **Action space** Retrieve (top_k/insight_k/hop variants), PlanInject, Re-Retrieve, Consolidate, Forget, NoOp, nine configurations ([arXiv HTML](https://arxiv.org/html/2607.13591)). **Training signal** episode-end reward r = 1.0·success + 0.3·max(0, 1 − T/T_max) − 0.5·failure, reverse-discounted to earlier memory decisions ([arXiv HTML](https://arxiv.org/html/2607.13591)). **Benchmarks** ALFWorld, PDDL, ScienceWorld, TriviaQA, WebWalkerQA, GAIA; ALFWorld 67.9% vs 59.7% for G-Memory, tokens down 5–20%, the learned controller contributing +5.2 points in ablation ([arXiv HTML](https://arxiv.org/html/2607.13591)). **Solves** a separate, non-LLM, learned controller on sequential tasks with an explicit Consolidate and Forget. **Leaves open** discretisation thresholds are benchmark-specific; baselines are nine memory systems plus "Empty," and an early PDF extraction claiming an oracle comparison was not supported by the fuller HTML extraction, so treat "no oracle" as the likelier reading ([arXiv HTML](https://arxiv.org/html/2607.13591)). **Differs** MemCon controls operations over an external store, not per-item retention under a hard active budget; its state is discretised and tabular whereas the project's is a set of 24-feature items; it has no archive/retrieve pair in the project's sense (retrieval is from the store, not from an archive the controller filled), no hindsight oracle, and no attribution. It is the closest precedent for "small learned controller over a frozen LLM on ALFWorld-style tasks," and its bandit-plus-reverse-discount signal is a simpler version of the project's PPO arm.

**EMBER.** Yilong Li, Suman Banerjee, Tong Che, "EMBER: Efficient Memory via Budgeted Evidence Retention for Long-Horizon Agents," arXiv 2606.05894, 2026, [arXiv HTML](https://arxiv.org/html/2606.05894). **Method** a separate writer LLM (Qwen2.5-7B/14B) distinct from a frozen retriever and reader chooses insert / merge / overwrite / skip over source excerpts under a fixed retained-evidence budget B_ret ∈ {512, …, 8192} tokens ([arXiv HTML](https://arxiv.org/html/2606.05894)). **Training signal** "answer-gated evidence-chain RL" with GRPO: answer-quality gate × (evidence survival, retrieval rank, selection purity) − budget penalty, budgets sampled uniformly ([arXiv HTML](https://arxiv.org/html/2606.05894)). **Benchmarks** LongMemEval-RR, RULER-HotpotQA 28K, MultiQ, explicitly "not sequential agent tasks"; baselines Random, Recency, Reservoir, hybrid salience, adapted MemAgent/Memory-R1/TierMem, plus **Oracle retention (gold evidence packed into budget)** as an upper bound and full-log RAG; at 8192 tokens EMBER-14B 0.3017 F1 vs 0.1765 best baseline, and EMBER-7B at 512 tokens beats the best baseline at 16x the budget ([arXiv HTML](https://arxiv.org/html/2606.05894)). It reports Retain-Recall (0.3215) and Read-Recall (0.3112) separately from F1, which is a placement-versus-retrieval split ([arXiv HTML](https://arxiv.org/html/2606.05894)). **Leaves open** by its own account selective retention can preserve stale or misleading evidence and needs deletion controls ([arXiv HTML](https://arxiv.org/html/2606.05894)). **Differs** EMBER's budget-sweep-with-oracle-bound protocol is the closest published template for the project's equal-budget comparison and should be cited as such; but its controller is a 7B–14B LLM, its oracle is gold-evidence packing rather than a furthest-next-use ILP, it has no archive, no sequential task, and no imitation arm.

**AdaCoM.** Lu Yi et al., "Learning Agent-Compatible Context Management for Long-Horizon Tasks," arXiv 2605.30785, 2026, [arXiv HTML](https://arxiv.org/html/2605.30785). A Qwen3-4B external manager edits a frozen agent's running context before each step via structured JSON operations (rewrite/merge, delete stale content, preserve constraints), trained by SFT then GRPO with a shaped reward (−0.8 for exceeding a 32K limit, −0.4 redundant tool call, −0.5 format); BrowseComp-Plus +39% average relative across four frozen agents ([arXiv HTML](https://arxiv.org/html/2605.30785)). Its "Fidelity–Reliability Trade-off" — managers for stronger agents keep 5.2–7.0K tokens while managers for weaker agents compress to 1.9–3.4K ([arXiv HTML](https://arxiv.org/html/2605.30785)) — is direct evidence that the optimal memory policy depends on the frozen task model, which supports the project's PPO-against-the-actual-task-model arm over pure oracle imitation. **Leaves open** knowledge-intensive search only, 4B capacity, per-step overhead, KV-cache invalidation. **Differs** an LLM manager that reads text versus a 27k-parameter controller that never does; no archive; no oracle; no attribution.

**MemSifter** (Jiejun Tan et al., arXiv 2603.03379, [URL](https://arxiv.org/html/2603.03379)) trains a Qwen3-4B proxy to select top-10 sessions for a frozen working LLM with a marginal-utility reward (accuracy with versus without retrieved memory) plus a DCG term, LoCoMo-32K 41.79 F1 vs 38.70 for Mem-α ([arXiv HTML](https://arxiv.org/html/2603.03379)); it is retrieval only, not placement, so it is the learned form of the project's retriever, which the project currently treats as a fixed bottleneck. **Hindsight Memory-PRM** (Haoxuan Jia et al., "Hindsight Memory-PRM: Supervising Memory Management with Auditable Hindsight Credit," arXiv 2608.29605, 2026, [URL](https://arxiv.org/html/2608.29605)) trains a Qwen3-8B LoRA policy emitting Write/Merge/Noop with a separate 1.7B critic, using "interventional self-supervision" — deleting cited entries and re-answering so that "a correct→wrong transition establishes that the entry is necessary" — with intervention-calibrated credit worth +7.3 pp over observational attribution; LoCoMo 77.5% vs a 65.1% API teacher; limits are schema specificity and a 0.6 credit cap on unmeasurable entries ([arXiv HTML](https://arxiv.org/html/2608.29605)). That delete-and-re-answer intervention is a one-action-deviation roll-out and is the closest published mechanism to the project's per-failure attribution, though it labels entries rather than failures. **Provider-routing MemAgent** (Yongxian Wei et al., "MemAgent: Learning to Manage Heterogeneous Memory Providers for LLM Agents," arXiv 2609.32521, 2026, [URL](https://arxiv.org/html/2609.32521v1), distinct from the ByteDance MemAgent) trains a Qwen3.5-4B LoRA router (0.84% of parameters) over 13 providers by forced exploration then reward-filtered SFT, and reports a **hindsight oracle of 89.6% vs 71.0% for the best single provider**, with the router at 75.7% ([arXiv HTML](https://arxiv.org/html/2609.32521v1)); reward-filtered SFT after exhaustive exploration is behaviour cloning of a hindsight-best choice, the closest existing instance of "imitate the hindsight decision" for a memory decision, though not DAgger and not over retention. **Differs** for all three: LLM-scale controllers, QA or search tasks, no active-context budget, no archive/evict pair.

**TraceRetain.** Pranath Reddy, "Selective Memory Retention for Long-Horizon LLM Agents," arXiv 2606.29178, 2026 (ICML 2026 per the RL note), [arXiv](https://arxiv.org/abs/2606.29178). A bounded external memory for a frozen ALFWorld agent scores entries by "success, age, access frequency, redundancy, specificity, similarity, downstream utility" and "evicts the lowest-scoring ones at capacity," with CEM-optimised weights; 47–49/50 vs 39/50 without memory; under a 75%-distractor noisy-write stress test bounded retention held 97/100 while unbounded memory's precision fell from 20.2% to 12.4%; the stated open question is when memory pollution "naturally emerges" ([arXiv](https://arxiv.org/abs/2606.29178)). Its null result — bounded policies are indistinguishable on clean streams and differ only under noise ([arXiv](https://arxiv.org/abs/2606.29178)) — is the warning that the project's 0.6 spread between policies at equal budget needs to be reported across budgets and distractor levels. **Differs** feature-weighted score with no archive, no oracle, no attribution; the project's age-decay/LFU/similarity/salience heuristics are individually the components TraceRetain combines.

**SOLAR** (Yushi Sun, Bowen Cao, Wai Lam, arXiv 2607.00394, [URL](https://arxiv.org/abs/2607.00394)) is a learning-augmented replacement policy for semantic retrieval buffers with competitive ratio at most 3 and eviction regret O(√(KT log T)), reporting that LRU and LFU "consistently underperform the naive FIFO baseline on semantic workloads" and 5–75% gains over FIFO on MemoryBench ([arXiv](https://arxiv.org/abs/2607.00394)). This is the only paper in the sweep that reports the same heuristic-ranking instability the project found, and it gives a theoretical reason. **ACON** (Minki Kang et al., "ACON: Optimizing Context Compression for Long-horizon LLM Agents," ICML 2026, arXiv 2510.00615, [URL](https://arxiv.org/abs/2510.00615)) uses no gradient RL: compression guidelines are refined in natural language from paired trajectories where full context succeeds and compressed context fails, then distilled; 26–54% peak-token reduction on AppWorld and OfficeBench ([arXiv](https://arxiv.org/abs/2510.00615)); the paired-trajectory contrast is a counterfactual failure signal, and ACON is a named LRE baseline. **OSL-MR** (Kang et al., "Learning What to Remember: Observability-Safe Memory Retention via Constrained Optimization for Long-Horizon Language Agents," arXiv 2606.10616, [URL](https://arxiv.org/abs/2606.10616)) frames retention as constrained stochastic optimisation with budget feasibility (shown NP-hard), separates "online-observable features and offline-available supervision" so the deployed policy uses only what it can see, and reports that a sequential formulation beats a single-step one on small solvable instances ([arXiv](https://arxiv.org/abs/2606.10616)); this is the same privileged-teacher/unprivileged-student structure as the project's DAgger arm, on LoCoMo and LongMemEval. **TRACER** (Ziqi Lin et al., "TRACER: Per-Tool Context Retention for LLM Agents via Consequence-Attributed Reinforcement Learning," arXiv 2608.29363, 2026, [URL](https://arxiv.org/abs/2608.29363)) names the "compression–consequence gap" and trains a lightweight REINFORCE policy assigning per-tool-output retention ratios with a learned outcome model comparing the chosen ratio to full retention; reward is task success plus total tokens plus re-invocations; 29–46% token reduction on multi-step enterprise sessions and LOCA-bench ([arXiv](https://arxiv.org/abs/2608.29363)). **MeClear** (Boyu Yang et al., arXiv 2609.09115, [URL](https://arxiv.org/abs/2609.09115)) uses leave-one-out and sampled Shapley attribution to suppress retrieved memories with negative utility from the active context "without permanently altering the persistent memory bank" ([arXiv](https://arxiv.org/abs/2609.09115)), a query-scoped reversible evict. **MemGen** (Guibin Zhang, Muxin Fu, Shuicheng Yan, arXiv 2509.24704, [URL](https://arxiv.org/html/2509.24704)) keeps the core LLM frozen and trains LoRA trigger and weaver modules that emit latent memory tokens; it is latent memory, not context eviction. **Differs** for the group: TRACER is the nearest on "separate lightweight RL policy with consequence-aware reward on sequential tasks," but its action is a continuous compression ratio with no archive and a soft token objective; ACON and OSL-MR supply counterfactual and observability-safe framings the project can cite for its DAgger arm; SOLAR supplies the theory behind the heuristic flip.

## Oracle diagnostics and failure attribution appear only in 2026 evaluation papers

No classic system reports an oracle bound or a failure taxonomy. Four 2026 evaluation papers do, and together they provide the vocabulary for the project's oracle and attribution arms; they also show the project's attribution scheme is finer than anything published.

**MemAudit.** Nishant Bhargava, Rodrigo Sobral Barrento, "MemAudit: An Exact Package-Oracle Evaluation Protocol for Budgeted Long-Term LLM Memory Writing," arXiv 2605.02199, 2026, [arXiv HTML](https://arxiv.org/html/2605.02199). **Problem** "downstream QA accuracy alone cannot identify which layer failed." **Method** an exact package oracle via MILP/branch-and-bound over a fixed candidate set, budget and future-query coverage; metric package ratio ρ = written-store value / OPT; certified equivalent to a pure-Python solver on 1,200 rows ([arXiv HTML](https://arxiv.org/html/2605.02199)). **Findings** Letta salience-pruned 0.881, Mem0 0.489; a density-only rule reaches 0.264–0.361 of OPT at tight budgets; omitting tombstone/validity candidates lowers OPT to 0.523–0.815 ([arXiv HTML](https://arxiv.org/html/2605.02199)). **Leaves open** the oracle needs "exact package-oracle marginals" unavailable to deployed systems and is "a certified upper bound for diagnostic purposes, not a prescriptive deployment algorithm"; systems "need estimated utilities, learned generators, compaction, or native budget-aware admission rather than oracle-computed densities" ([arXiv HTML](https://arxiv.org/html/2605.02199)). **Differs** MemAudit's exact MILP oracle is the same construction as the project's exact ILP delete-only oracle, so the project cannot claim the oracle as new; the difference is that the project uses the oracle as a DAgger teacher and finds it is the wrong target once archiving exists, which MemAudit's "diagnostic, not prescriptive" remark anticipates without testing. MemAudit is write-side only and has no sequential task.

**Restore-counterfactual audit.** Chen Shen, "What Eviction Destroys: A Restore-Counterfactual Audit of Forgetting in Agent Memory," arXiv 2609.08279, 2026, [arXiv](https://arxiv.org/abs/2609.08279). **Method** reinstate the needed evidence at read time and rerun, splitting failures into irreversible (evicted), recoverable (retrieval miss) and residual, for FIFO, random, redundancy-aware and LLM-importance eviction on LongMemEval-S with a GPT-4o-mini reader ([arXiv](https://arxiv.org/abs/2609.08279)). **Findings** at 80k tokens under top-k retrieval the irreversible share among restoration-corrected errors is 0.67–0.73 for FIFO/random/redundancy-aware versus 0.60 for LLM-importance; at 8k tokens irreversibility is 1.00 for every policy ([arXiv](https://arxiv.org/abs/2609.08279)). **Differs** this three-way split (evicted / retrieval miss / residual) is a coarse version of the project's seven-way attribution (`evicted`, `archived_not_retrieved`, `retrieved_but_ignored`, `task_model_reasoning`, plus compression, consolidation and invalid-action classes), on QA rather than a sequential task, and with no learned policy. The project must cite it as the prior attribution protocol and position its own as a refinement; the 1.00 irreversibility result at 8k also predicts the project's finding that at tight budgets nothing but an archive helps.

**MemTrace.** Xinle Deng et al. (18 authors incl. Ningyu Zhang), "MemTrace: Tracing and Attributing Errors in Large Language Model Memory Systems," arXiv 2605.28732, 2026, [arXiv](https://arxiv.org/abs/2605.28732). Introduces error tracing and attribution with MemTraceBench over long-context, RAG, Mem0 and EverMemOS, attributing failures to "operation-level issues like information loss and retrieval misalignment," with attribution-driven fixes worth up to 7.62% ([arXiv](https://arxiv.org/abs/2605.28732)). Whether it separates "reasoning failure given correct memory" from memory failure could not be determined from the abstract. Note the benchmarks note lists a "MemTrace" at arXiv 2606.17328 ([URL](https://arxiv.org/pdf/2606.17328)); the two IDs were not reconciled and should be checked before citing. **Differs** MemTrace attributes at the operation level for prompted systems; the project attributes per failure for a learned controller and includes `retrieved_but_ignored` and `task_model_reasoning`, which separate the controller from the task model.

**The Epistemics of Agent Memory.** Sasank Annapureddy, Anjaneya Prasad Thamatani, arXiv 2609.33013, 2026, [arXiv](https://arxiv.org/abs/2609.33013). Action space "what to keep, compress, abstract into reusable skills and rules, or forget"; Phase 2 learns promotion "under a token budget" for a verified +22.7% task success at 7x compression while exposing a degenerate-forgetting failure; Phase 3 introduces ConsolidationBench, "an oracle-by-construction benchmark that scores consolidation decisions against a known optimum," on which "production retrieval systems retain information yet score zero on cross-level transfer"; and it reports a resolved negative, that its quality score "does not predict real transfer accuracy (pooled Spearman ρ = −0.24, n = 12, CI spanning zero)" ([arXiv](https://arxiv.org/abs/2609.33013)). **Differs** the closest published work on learned CONSOLIDATE under a budget with an oracle-by-construction benchmark; the project's `consolidation_incorrect` class measures the same failure but the project's consolidation is one of seven actions rather than the object of study.

Three further 2026 papers reframe the problem in ways the project should cite. Colaco and Lahjouji's rate–distortion view ("What to Keep, What to Forget," arXiv 2607.08032, [URL](https://arxiv.org/abs/2607.08032)) unifies KV eviction, prompt pruning and agent consolidation and finds the keep signal "fails in the same way everywhere, by discarding, before the query is known and with no way to undo it, information the query later needs," that repeated compaction "is almost never measured," and (per the HTML) that "under repeated irreversible summarization, end-task error grows super-linearly in the number of compaction events, whereas a reversible, retrieval-backed memory stays flat" ([arXiv HTML](https://arxiv.org/html/2607.08032v1)); this is the theoretical case for the project's ARCHIVE-versus-EVICT distinction. Zou et al.'s "Remember the Decision, Not the Description" (arXiv 2605.10870, [URL](https://arxiv.org/abs/2605.10870)) defines decision-relevant distortion and an "exact forgetting boundary" with a near-minimax online learner. Liu's "What Does Context Compression Cost an Agent?" (arXiv 2608.16370, [URL](https://arxiv.org/pdf/2608.16370)) shows compression induces re-retrieval loops and extra steps invisible to task-completion metrics, which is what the project's sequential task turns into job restarts. ForgetEval (Dongxu Yang, arXiv 2606.15903, [URL](https://arxiv.org/abs/2606.15903)) states "production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall" over 1,385 cases. The Human-Inspired Memory Architecture (Doga Kerestecioglu et al., arXiv 2605.08538, [URL](https://arxiv.org/abs/2605.08538)) is the one prompted system evaluated at an explicit 200K-token budget on LongMemEval M-tier streaming (70.1% vs 71.2% raw retrieval) with a tunable accuracy/store-size curve ([arXiv](https://arxiv.org/abs/2605.08538)); its graded fidelity levels from full record to tombstone appeared only in a search snippet and are unverified. **Differs** for the group: they measure or theorise the cost of irreversible compaction; the project makes reversibility an action and measures it per failure.

## Most memory benchmarks are ingest-then-probe; five 2026 suites make forgetting change the trajectory

The project's two benchmark adapters and its sequential synthetic task sit on opposite sides of a distinction the benchmark literature has only recently drawn. **LoCoMo** (Adyasha Maharana, Dong-Ho Lee, Sergey Tulyakov, Mohit Bansal, Francesco Barbieri, Yuwei Fang, "Evaluating Very Long-Term Conversational Memory of LLM Agents," ACL 2024, [ACL Anthology](https://aclanthology.org/2024.acl-long.747/), [arXiv](https://arxiv.org/abs/2402.17753)) has 50 generated conversations averaging 19.3 sessions and 9,209 tokens with 7,512 questions in five categories, but the released `locomo10` subset has 10 conversations ([GitHub](https://github.com/snap-research/locomo)) and an independent audit counts 1,540 released questions, of which 99 (6.4%) have score-corrupting answer-key errors, with the gpt-4o-mini judge accepting 62.81% of deliberately wrong but adjacent answers and a theoretical ceiling near 93.6% ([Penfield audit](https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg); [GitHub issue #27](https://github.com/snap-research/locomo/issues/27)). Crucially for the project, **each QA is annotated with the turn IDs containing the answer** ([arXiv PDF](https://arxiv.org/pdf/2402.17753)), which is what makes the project's evidence-retention metric and its oracle computable. **LongMemEval** (Di Wu et al., ICLR 2025, [ICLR](https://iclr.cc/virtual/2025/poster/28290), [GitHub](https://github.com/xiaowu0162/longmemeval)) has 500 questions over ~40-session (S, ~115k tokens) or ~500-session (M) histories, dual-level evidence labels (`answer_session_ids` plus per-turn `has_answer`), a GPT-4o judge, and a documented 2025 cleanup of distractor sessions ([GitHub](https://github.com/xiaowu0162/longmemeval)); MemDelta shows its rankings flip on the embedding model alone, a 6.2-point swing ([arXiv](https://arxiv.org/html/2606.29914v1)). The Zep–Mem0 dispute over whether adversarial Category 5 belongs in the LoCoMo numerator (84% vs 58.44% vs 75.14%) ([Zep issue #5](https://github.com/getzep/zep-papers/issues/5); [Zep blog](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)) is a second reason the project's choice to report evidence-retention rather than judged QA on these adapters is defensible. **How the project differs** in use: the project uses both datasets only for evidence-retention under a budget with no LLM task model, which sidesteps judge leniency and label noise but also means the project cannot yet claim task-level results on them; the ~7-point noise floor implied by the audit bounds what a future LLM-judged comparison could resolve.

The other probe-after-history suites are relevant only as scope boundaries. MemoryAgentBench (Yuanzhe Hu, Yu Wang, Julian McAuley, ICLR 2026, arXiv 2507.05257, [URL](https://arxiv.org/abs/2507.05257)) delivers 12 datasets in sequential chunks with a "please memorize" instruction and a selective-forgetting competency, but "does not describe agents' actions affecting subsequent context" ([arXiv HTML](https://arxiv.org/html/2507.05257)). MemBench (arXiv 2506.21605, [URL](https://arxiv.org/abs/2506.21605)), BEAM with 10M-token conversations (arXiv 2510.27246, [URL](https://arxiv.org/abs/2510.27246)), EverMemBench (arXiv 2602.01313, [URL](https://arxiv.org/abs/2602.01313)), LoCoMo-Plus (ACL 2026, arXiv 2602.10715, [URL](https://arxiv.org/abs/2602.10715), with 30–46 point factual-to-cognitive drops), the episodic-memory benchmark (Huet et al., ICLR 2025, arXiv 2501.13121, [URL](https://arxiv.org/abs/2501.13121)), LongMemEval-V2 over web-agent trajectories (arXiv 2605.12493, [URL](https://arxiv.org/abs/2605.12493)), AMA-Bench over agent trajectories (ICML 2026, arXiv 2602.22769, [URL](https://arxiv.org/html/2602.22769v4)) and the long-context suites LongBench, RULER, NoLiMa, BABILong and HELMET are all fixed-history probes; the synthetic ones (episodic, AMA synthetic split, BABILong) give evidence labels by construction. MemoryBench (Ai et al., ICML 2026 spotlight per search summary, arXiv 2510.17281, [URL](https://arxiv.org/abs/2510.17281)) has an on-policy regime that is a closed loop, but it is continual learning from feedback rather than memory-dependent action.

The 2026 cohort that makes forgetting change the trajectory is the right comparison class for the project's sequential workflow task. **MemoryArena** (Zexue He et al., ICML 2026, arXiv 2602.16313, [URL](https://arxiv.org/abs/2602.16313)) builds a "Memory-Agent-Environment loop" with "explicitly interdependent subtasks" across web shopping, preference-constrained planning, progressive search and sequential formal reasoning, and reports that "agents with near-saturated performance on existing long-context memory benchmarks like LoCoMo perform poorly in our agentic setting" ([arXiv](https://arxiv.org/abs/2602.16313)); the Du survey cites the drop as from near-perfect to 40–60% ([arXiv HTML](https://arxiv.org/html/2603.07670v1)). **Mem2ActBench** (ACL 2026, arXiv 2601.19935, [URL](https://arxiv.org/abs/2601.19935)) tests whether memory is used to select a tool and fill its parameters over 2,029 sessions and 400 tasks, 91.3% judged strongly memory-dependent, finding seven frameworks "remain inadequate at actively utilizing memory for parameter grounding" ([arXiv](https://arxiv.org/abs/2601.19935)). **MERIT** (Mishra and Mishra, "When Does Memory Help? A Cost-Aware Evaluation of Long-Term Memory in Tool-Using LLM Agents," arXiv 2609.05441, [URL](https://arxiv.org/abs/2609.05441)) measures marginal utility on dependent tasks, where memory lifted success from 0.00 to 0.55–1.00, swapping the memory implementation moved success by up to 60 points, and **agents acted on correctly retrieved values only 55% of the time** ([arXiv](https://arxiv.org/abs/2609.05441)); that last number is the published form of the project's `retrieved_but_ignored` class, and the 60-point swing is the published analogue of the project's 0.6 spread between policies. **MemGym** (Wujiang Xu et al., arXiv 2605.20833, [URL](https://arxiv.org/abs/2605.20833)) is an environment with five tracks and "memory-isolated scores that decouple memory performance from reasoning, retrieval, and tool-use ability," plus a Qwen3-1.7B reward model for compression quality ([arXiv](https://arxiv.org/abs/2605.20833)), built for training controllers. **PM-Bench** (Liu and Gabriel, COLM 2026, arXiv 2607.12385, [URL](https://arxiv.org/abs/2607.12385)) tests prospective memory in a Virtual-Week paradigm with F1 on executed intentions, best model 65.1% ([arXiv](https://arxiv.org/abs/2607.12385)). **How the project differs**: the project's sequential task is a scripted environment with the same trajectory-dependence property and a known oracle, which the researchers note is what makes the oracle recomputable on learner rollouts; the cost is that no result on MemoryArena, Mem2ActBench, MERIT, MemGym or PM-Bench exists yet, and the project cannot claim its sequential finding transfers until one of them is run. MemGym is the natural next environment because it was built for exactly this.

## Caching and KV eviction supply the Belady recipe and its known failure modes

The project's training recipe is not new; it is Parrot's, and the caching literature has already documented most of the failure modes the project reports. **Belady's MIN** (L. A. Belady, "A Study of Replacement Algorithms for a Virtual-Storage Computer," IBM Systems Journal 5(2):78–101, 1966, [Semantic Scholar](https://www.semanticscholar.org/paper/A-Study-of-Replacement-Algorithms-for-Computer-Belady/7779c10dfa1f84953016b6292844815c5faf84f5)) evicts the page whose next use is farthest in the future given the full reference string; Hawkeye's abstract states it "is optimal but infeasible because it requires knowledge of the future" ([Hawkeye PDF](https://www.cs.utexas.edu/~lin/papers/isca16.pdf)), and reproducing it needs a lookahead of about 8x the cache size ([Hawkeye PDF](https://www.cs.utexas.edu/~lin/papers/isca16.pdf); [Mockingjay PDF](https://www.cs.utexas.edu/~lin/papers/hpca22.pdf)), or 2,600 accesses on omnetpp for 80% of Belady's benefit ([Parrot PDF](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)). The project's furthest-next-use oracle is MIN by another name and should be cited as such.

**Parrot.** Evan Zheran Liu, Milad Hashemi, Kevin Swersky, Parthasarathy Ranganathan, Junwhan Ahn, "An Imitation Learning Approach for Cache Replacement," ICML 2020, PMLR 119, arXiv 2006.16239, [PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf), [arXiv](https://arxiv.org/abs/2006.16239). **Problem** learn a replacement policy that approximates Belady. **Method** an MDP whose state is the current access, the W lines in the set and the last H accesses; action at a miss is which line to evict, no-op at a hit; reward 1 per hit ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)). **Training signal** Belady's action at each visited miss state computed from the fixed future sequence; **DAgger**, recollecting states under the current learned policy every 5,000 updates because following Belady "leads to compounding errors," possible because "we can compute our oracle policy (Belady's) at any state during training, as long as the future accesses are known"; on-policy collection gives 9.8% higher normalised hit rate on average, but "this is highly program-dependent … in some programs, like mcf or Web Search, training off-policy performs as well or better" ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)). A ranking loss with reuse distance as relevance beats log-likelihood on Belady's argmax by 3.5%, and predicting reuse distance as an auxiliary loss beats evicting by it directly because "small errors may drastically affect which line is evicted" ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)). **Benchmarks** 13 SPEC2006 programs, +16% raw hit rate over LRU and +20% normalised over Glider (the abstract's "increases cache miss rates by 20%" is a wording slip) ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)). **Leaves open** deployment latency; single-level replacement, with prefetching named as the other avenue. **Differs** Parrot is the direct methodological ancestor of the project's DAgger arm and the project should say so; three things differ. First, Parrot's access stream "is independent of the action a_t and is defined by the program being executed" ([PMLR](http://proceedings.mlr.press/v119/liu20f/liu20f.pdf)), whereas the project's sequential task makes the stream depend on the controller, which is exactly why the project found the oracle blind after divergence and why it needs a simulator to recompute the oracle. Second, Parrot has a single evict action; the project has seven including reversible archive. Third, Parrot's finding that the DAgger benefit is program-dependent predicts the project's finding that imitation matches but does not beat the best heuristic on one task and dominates on the other.

**Hawkeye, Glider, Mockingjay.** Akanksha Jain and Calvin Lin, "Back to the Future: Leveraging Belady's Algorithm for Improved Cache Replacement," ISCA 2016, [PDF](https://www.cs.utexas.edu/~lin/papers/isca16.pdf), [ACM](https://dl.acm.org/doi/10.1109/ISCA.2016.17): OPTgen reconstructs what MIN would have done on the *past* window to label each load cache-friendly or cache-averse and trains a PC-indexed predictor online, reproducing MIN on past accesses with 99% accuracy in 16KB and gaining 8.4% IPC over LRU. Zhan Shi, Xiangru Huang, Akanksha Jain, Calvin Lin, "Applying Deep Learning to the Cache Replacement Problem," MICRO 2019, [PDF](https://www.cs.utexas.edu/~lin/papers/micro19c.pdf): an offline attention LSTM on Belady labels (82.6% vs 72.2% for Hawkeye's predictor) whose interpretation yields an online integer SVM, because deep models are too big for hardware. Ishan Shah, Akanksha Jain, Calvin Lin, "Effective Mimicry of Belady's MIN Policy," HPCA 2022 (venue inferred from the author-site filename), [PDF](https://www.cs.utexas.edu/~lin/papers/hpca22.pdf): predicts per-PC reuse distance and evicts the line predicted farthest away, arguing binary labels flip on small errors and tie-break to LRU; +15.2% over LRU on a 4-core mix vs 12.9% for Hawkeye, and single-core 5.7% against MIN's unrealisable 6.0%. **Differs** the project's per-item features (24, including age and use counts) are the memory-controller analogue of Hawkeye's PC-indexed features; the Hawkeye-to-Mockingjay progression from binary to ranking labels is a warning that the project's oracle labels should be rankings or acceptable sets, not a single argmax.

**LRB (Learning Relaxed Belady).** Zhenyu Song, Daniel S. Berger, Kai Li, Wyatt Lloyd, "Learning Relaxed Belady for Content Distribution Network Caching," NSDI 2020, [USENIX PDF](https://www.usenix.org/system/files/nsdi20-paper-song.pdf). Motivated by a "25–40% gap between Belady and all other policies," it argues exact imitation is impractical because "an ML predictor needs to predict the time to next request of all objects in the cache accurately," so it relaxes MIN to a Belady boundary (2–3x cache size; 10–19% of objects beyond it are evicted at random, costing 9–13% byte misses vs MIN), decouples unlabelled snapshots from delayed labels, trains LightGBM on log time-to-next-request, and cuts WAN traffic 4–25% in simulation and 44% in an Apache Traffic Server prototype ([USENIX PDF](https://www.usenix.org/system/files/nsdi20-paper-song.pdf)). **Differs** the project imitates the exact furthest-next-use argmax; LRB's relaxation and its "good decision ratio" are the labelling trick the project could adopt to make its labels available online, and its 9–13% relaxation cost quantifies what that would give up.

**Online and expert-mixture caching.** LeCaR (Vietri et al., HotStorage 2018, [PDF](https://www.usenix.org/system/files/conference/hotstorage18/hotstorage18-paper-vietri.pdf)) does regret minimisation over LRU and LFU experts, and Cacheus (Rodriguez et al., FAST 2021, [PDF](https://www.usenix.org/system/files/fast21-rodriguez.pdf)) finds LeCaR "underperforms state-of-the-art algorithms such as ARC, LIRS, and DLIRS for many production workloads," that the optimal learning rate varies across workloads and over time, and classifies workloads into LRU-friendly, LFU-friendly, scan and churn primitives over 17,766 simulations ([FAST PDF](https://www.usenix.org/system/files/fast21-rodriguez.pdf)). RL-Cache (Kirilin et al., IEEE JSAC 2020, [dblp](https://dblp.org/rec/journals/jsac/KirilinSGS20.html)) learns admission. Paschos et al., "Learning to Cache With No Regrets," INFOCOM 2019 ([arXiv](https://arxiv.org/pdf/1904.09849)) and Lykouris and Vassilvitskii, "Competitive Caching with Machine Learned Advice," ICML 2018 / J. ACM 2021 ([arXiv](https://arxiv.org/pdf/1802.05399)) give the regret and competitive-ratio theory, the latter showing performance degrades gracefully as O(1+min(√(η/OPT), log k)) in prediction error η. **Differs** the project's heuristic-ranking flip between tasks is the Cacheus workload-primitive finding in a memory setting; LeCaR/Cacheus are the natural next baseline (an online mixture over the project's own heuristics) and the project has not run it.

**Oracles that change when a fetch channel exists.** Jain and Lin, "Rethinking Belady's Algorithm to Accommodate Prefetching," ISCA 2018 ([ACM](https://dl.acm.org/doi/10.1109/ISCA.2018.00020)) shows that with a prefetcher MIN "does not minimize the number of demand misses," and Demand-MIN is the corrected oracle. "Beyond Belady" (arXiv 2212.13671, [HTML](https://arxiv.org/html/2212.13671v1)) shows that with variable object sizes an online policy can beat MIN's byte miss ratio, so "imitate MIN" can be the wrong target even with perfect imitation. Joint eviction-admission-prefetch learning exists only as preliminary work (DEAP Cache, arXiv 2009.09206, [URL](https://arxiv.org/abs/2009.09206); Yuan et al., NeurIPS 2025 ML-for-Systems workshop, arXiv 2510.10862, [URL](https://arxiv.org/abs/2510.10862)). **Differs** Demand-MIN is the closest published precedent for the project's finding that imitating the hindsight deletion expert is the wrong target once archiving exists: adding a retrieve channel changes what the hindsight-optimal policy is. The project should state its finding as the memory-control instance of Demand-MIN rather than as a new phenomenon, and should note that its items are variable-size like CDN objects, so a size-aware oracle (PFOO-style, not fetched) is the relevant reference.

**Bounded-memory learning theory.** Bhattacharjee and Mahajan, "Learning what to remember," ALT 2022, arXiv 2201.03806 ([arXiv](https://arxiv.org/abs/2201.03806); [PMLR](https://proceedings.mlr.press/v167/bhattacharjee22a/bhattacharjee22a.pdf)) is the abstract form of the project's recall task: a learner sees a stream of facts, retains a bounded number, is charged on questions about forgotten facts, and competes against memory-constrained experts in hindsight; multiplicative weights is shown to be problematic and a near-optimal-regret scheme is given. Toro Icarte et al., "The act of remembering," arXiv 2010.01753 ([listing](https://awesomepapers.io/reinforcement-learning/papers/2010.01753)), gives an RL agent explicit write actions over external memory and shows that with expressive enough memory optimal memoryless policies are globally optimal; Kara and Yüksel, JMLR 2022 ([JMLR](https://www.jmlr.org/papers/volume23/20-1152/20-1152.pdf)) show finite-window policies are near-optimal under filter stability. **Differs** these give the project a formal frame (a controller is a policy over write/evict actions in a POMDP whose optimum needs the future query); none has an archive tier or an LLM task model.

**KV-cache eviction.** The 2023–2024 methods — H2O (arXiv 2306.14048, NeurIPS 2023 venue unverified, [URL](https://arxiv.org/abs/2306.14048)), Scissorhands (arXiv 2305.17118, [URL](https://arxiv.org/abs/2305.17118)), StreamingLLM (ICLR 2024, [URL](https://arxiv.org/abs/2309.17453)), FastGen (ICLR 2024, [URL](https://arxiv.org/abs/2310.01801)), SnapKV (arXiv 2404.14469, [URL](https://arxiv.org/abs/2404.14469)), PyramidKV ([URL](https://arxiv.org/abs/2406.02069)), Keyformer (MLSys 2024, [URL](https://arxiv.org/abs/2403.09054)), TOVA (arXiv 2401.06104, [URL](https://arxiv.org/abs/2401.06104)) — are training-free heuristics scoring tokens by past attention plus recency with no recovery path; Scissorhands states the assumption outright, that "only pivotal tokens, which had a substantial influence at one step, will significantly influence future generations" ([arXiv](https://arxiv.org/abs/2305.17118)). Quest (ICML 2024, [URL](https://arxiv.org/abs/2406.10774)) and InfLLM (arXiv 2402.04617, [URL](https://arxiv.org/abs/2402.04617)) are the KV-level archive-and-retrieve analogues, never deleting but skipping or offloading pages and re-fetching by query. DMC (ICML 2024, [URL](https://arxiv.org/abs/2403.09636)) learns per-head append-or-accumulate from the LM loss. The 2026 learned wave reproduces the caching pipeline at token granularity: **ForesightKV** (Dong et al., ICML 2026, arXiv 2602.03203, [URL](https://arxiv.org/abs/2602.03203)) states "KV importance is a function of future attention scores, yet existing methods only see historical information," computes Golden Eviction offline from the complete trace, supervises a lightweight scorer with a pairwise ranking loss, then applies GRPO because SL alone left "significant language modeling loss increase on low-entropy tokens" ([arXiv HTML](https://arxiv.org/html/2602.03203v2)); **KVP** (Moschella, Manduchi, Sener, "Learning to Evict from Key-Value Cache," ICML 2026, [URL](https://arxiv.org/abs/2602.10238)) trains a per-head RL agent to rank tokens with "a holistic reward, derived from future utility"; **KVpop** (Hauzenberger et al., arXiv 2607.05061, [URL](https://arxiv.org/abs/2607.05061)) supervises keep-or-drop with a future-attention target and a delayed scorer; **DistillCache** (Althoubi, arXiv 2608.08878, [URL](https://arxiv.org/abs/2608.08878)) trains an MLP policy over attention mass, value norm, entropy and position with REINFORCE on a KL-to-full-cache reward; **MemDecay** (Matam and Kim, arXiv 2607.10582, [URL](https://arxiv.org/abs/2607.10582)) is training-free but measures that attention half-lives differ by context region — 148–189 decoding steps for system tokens vs 14–16 for scratchpad tokens ([arXiv](https://arxiv.org/abs/2607.10582)), the only direct evidence found that agent-context items have heterogeneous lifetimes. **Differs** ForesightKV's SL-on-oracle-then-RL is structurally identical to the project's imitation-then-PPO plan, and the project should cite it as the KV-level twin; the differences are granularity (tokens vs typed items), "future importance" meaning future attention rather than task success, and the absence of any archive, so evicted tokens are gone. DistillCache's feature-based MLP policy is the closest architectural analogue to the project's DeepSets controller. MemDecay's half-life result supports the project's per-item type features.

## Imitation-gap theory predicts where hindsight imitation fails and how to fix it

The project's finding that imitation matches the best heuristic on the recall task but does not beat it, and that the hindsight oracle is blind once the trajectory diverges, has a formal explanation that the researchers found stated cleanly in one paper and nowhere applied to memory. Weihs et al., "Bridging the Imitation Gap by Adaptive Insubordination," NeurIPS 2021 ([NeurIPS](https://proceedings.neurips.cc/paper/2021/hash/9fc664916bce863561527f06a96f5ff3-Abstract.html); [arXiv](https://arxiv.org/abs/2007.12173)) define the imitation gap as π_f^IL ≠ π^teach when the teacher's filtration is richer than the student's, and prove Proposition 1 (Policy Averaging): with a sufficiently rich student class, **π_f^IL(o) = E_µ[π^teach(S) | f(S) = o]**, the privileged information is marginalised out ([arXiv PDF](https://arxiv.org/pdf/2007.12173)). Their Poisoned Doors example shows the imitating student can obtain expected return −2·(N−3)/(N−1) where the optimal unprivileged policy gets 1, and that "training with reward-based RL after a 'warm start' with IL is strictly worse than starting without it" ([arXiv PDF](https://arxiv.org/pdf/2007.12173)); ADVISOR fixes this by adaptively weighting IL and RL losses by an estimated gap. A hindsight furthest-next-use oracle is exactly a teacher whose filtration includes the future query; where that query is unpredictable from the past, the DAgger student learns the average of the oracle's action over consistent futures, which is what a well-tuned heuristic already approximates. That is the mechanism behind "imitation matches but does not beat the best heuristic," and Poisoned Doors is a specific warning that the project's IL-then-PPO ordering can hurt. Three refinements sharpen the test. Cai, Liu, Oikonomou, Zhang, "Provable Partially Observable Reinforcement Learning with Privileged Information," NeurIPS 2024 ([PDF](https://proceedings.neurips.cc/paper_files/paper/2024/file/74d188c51d97fcfbc0269f584d6a53b7-Paper-Conference.pdf)) formalise expert distillation, "demonstrating its pitfall in finding near-optimal policies," and give the deterministic filter condition under which it is sound: if the privileged variable is a deterministic function of the student's history, distillation works; the project's recall task (where future use is predictable from item features) versus its sequential task is a natural instance. Swamy, Choudhury, Bagnell, Wu, "Sequence Model Imitation Learning with Unobserved Contexts," 2022 (NeurIPS 2022 venue unverified; [arXiv](https://arxiv.org/abs/2208.02225)) prove that off-policy IL "treat[s] their suboptimal past actions as though they came from the expert" and latches, while on-policy IL provably recovers, which is the justification for DAgger over behaviour cloning in the project. Vuorio et al., "A Bayesian Solution To The Imitation Gap," arXiv 2407.00495 ([URL](https://arxiv.org/abs/2407.00495)) note the expert never demonstrates information-gathering; for a memory controller, "retrieve to check" is exactly the action a hindsight oracle never takes. The remedies in the robotics literature — Learning by Cheating (Chen et al., CoRL 2019, [PMLR](https://proceedings.mlr.press/v100/chen20a.html)), asymmetric actor-critic (Pinto et al., [arXiv](https://arxiv.org/abs/1710.06542)), A2D (Warrington et al., ICML 2021, [PMLR](https://proceedings.mlr.press/v139/warrington21a.html)), COSIL (Nguyen et al., CoRL 2022, [arXiv](https://arxiv.org/abs/2211.01991)), Privileged Sensing Scaffolds (Hu et al., ICLR 2024, [arXiv](https://arxiv.org/abs/2405.14853)), and "Distilling Realizable Students from Unrealizable Teachers" (Kim et al., [arXiv](https://arxiv.org/abs/2505.09546), which notes DAgger "querying experts at random states leads to datasets that become increasingly unrealizable") — map onto controller designs the project has not tried: a privileged critic with an unprivileged policy, an oracle recomputed over what is predictable from the past, or imitation gated by estimated gap. **How the project differs** from this literature: none of it is about memory; the mapping is the researchers' inference and should be presented as such. The project's contribution here is empirical, an instance of the imitation gap in memory control, and it should be framed with Weihs et al.'s Proposition 1 rather than as a surprise.

The algorithms themselves are standard and should be cited from the originals: DAgger (Ross, Gordon, Bagnell, AISTATS 2011, [arXiv](https://arxiv.org/abs/1011.0686)), which follows SMILe's O(T²) regret result for naive supervised imitation (Ross and Bagnell, AISTATS 2010, [PMLR](https://proceedings.mlr.press/v9/ross10a.html)); AggreVaTe (Ross and Bagnell 2014, [arXiv](https://arxiv.org/pdf/1406.5979)), which minimises the expert's cost-to-go rather than 0–1 mismatch and so tolerates suboptimal experts; Deeply AggreVaTeD (Sun et al., ICML 2017, [arXiv](https://arxiv.org/abs/1703.01030)), which "can achieve superior performance with respect to the oracle when the demonstrator is sub-optimal"; and LOLS (Chang, Krishnamurthy, Agarwal, Daumé III, Langford, "Learning to Search Better than Your Teacher," ICML 2015, [PMLR](https://proceedings.mlr.press/v37/changb15.html)), which rolls in with the learned policy, rolls out one-step deviations, and "can improve upon the reference policy, unlike previous algorithms." AggreVaTe and LOLS are directly relevant to the project's finding that the hindsight deletion expert is the wrong target: both are designed for a suboptimal reference and label per-decision regret by roll-out, which is what would let the project keep the oracle as a teacher while learning to archive. Memory-R2's local re-rollouts ([arXiv](https://arxiv.org/abs/2605.21768)) and Memory-PRM's delete-and-re-answer ([arXiv HTML](https://arxiv.org/html/2608.29605)) are the 2026 memory-specific instances of that construction. "Revisiting DAgger in the Era of LLM-Agents" (Changhao Li et al., arXiv 2605.12913, [URL](https://arxiv.org/abs/2605.12913)) adapts DAgger to multi-turn LLM agents with turn-level teacher/student interpolation (SWE-bench Verified +3.9 for 4B) but not to memory control; it is the closest methodological precedent for DAgger in the agent setting.

On credit assignment inside the PPO arm, the agentic-RL evidence is that terminal reward alone is a poor signal for long chains: Wei et al., arXiv 2505.11821 ([URL](https://arxiv.org/abs/2505.11821); NeurIPS 2025 per search results) find "dense per-turn reward structures consistently outperform sparse terminal and delayed reward structures"; GiGPO (Feng et al., NeurIPS 2025 per hosted PDF, [arXiv](https://arxiv.org/abs/2505.10978)) gains over 12% on ALFWorld by grouping repeated anchor states across rollouts; HCAPO (Tan et al., arXiv 2603.08754, [URL](https://arxiv.org/abs/2603.08754)) uses an LLM as a post-hoc critic for +13.8% on ALFWorld; RAGEN (Wang et al., arXiv 2504.20073, [URL](https://arxiv.org/abs/2504.20073)) documents the "Echo Trap" of reward-variance cliffs. The one dissent, Zhou et al., "Coverage, Not Targeting," arXiv 2609.02417 ([URL](https://arxiv.org/abs/2609.02417)), finds with terminal verifiers that uniformly spread dense reward beats sparse outcome, and that concentrating advantage "on progress turns or on random turns is equally harmful." The classical estimators are HCA (Harutyunyan et al., NeurIPS 2019, [arXiv](https://arxiv.org/abs/1912.02503)), Counterfactual Credit Assignment (Mesnard et al., ICML 2021, [arXiv](https://arxiv.org/abs/2011.09464)) and RUDDER (Arjona-Medina et al., [arXiv](https://arxiv.org/abs/1806.07857)); Hindsight Experience Replay ([arXiv](https://arxiv.org/abs/1707.01495)) is a different sense of "hindsight" (goal relabelling) and should not be conflated. **How the project differs**: the project's PPO arm uses task reward with a forced-fallback penalty and, per the notes, no dense per-decision credit; every memory-specific RL paper of 2026 (Mem-T, HiMPO, Memory-R2, UMA, MemCon's reverse discounting) densifies, and no paper anywhere was found that ablates immediate versus delayed reward or discount factor specifically for memory decisions, so that ablation is open.

## Conclusion

The sweep changes how the project's contribution should be stated. The "small learned controller" idea belongs to LRE and MemCon, the exact ILP oracle belongs to MemAudit, the imitation-then-RL recipe belongs to Parrot and ForesightKV, the evicted-versus-retrieval-miss attribution belongs to the restore-counterfactual audit, and the "do not throw evidence away" principle belongs to Memex(RL). What survives as the project's own ground is the conjunction and three empirical results that no neighbour reports: a seven-action policy in which reversible archive competes with irreversible evict and compact under one hard budget, attributed per failure; the demonstration that a Belady-style deletion oracle is the wrong imitation target once an archive exists, which Demand-MIN predicted for prefetching in 2018 and which nobody has shown for agent memory; and the observation that the hindsight oracle becomes undefined once the controller's choices change the observation stream, which every caching paper avoids by assumption and which Memory-R2 names but does not measure. The heuristic-ranking flip between tasks is corroborated by SOLAR and Cacheus and should be presented as confirmation, not discovery.

Two implications follow for what to do next. Theory says the imitation arm is bounded by Proposition 1 and will not beat a heuristic wherever future use is unpredictable from item features, so effort should go to the AggreVaTe/LOLS form of oracle supervision (cost-to-go or one-step-deviation regret, which Memory-R2 and Memory-PRM already compute for memory writes) and to a privileged critic with an unprivileged policy, rather than to more DAgger. And the evaluation gap that the field's 2026 benchmarks expose cuts against the project as much as against everyone else: MemoryArena, Mem2ActBench, MERIT and MemGym exist precisely to test whether forgetting changes actions, and until the controller is run on one of them with an LLM task model, the sequential-task result rests on a scripted environment whose closest published analogue, Memex(RL)'s modified ALFWorld, was solved by training the task model instead.

## Appendix 2. Likely overlaps, likely distinctions, and unresolved novelty risks

**Likely overlaps (do not claim these as new).**
1. A small, language-model-free, feature-based retention scorer under a hard budget, trained from hindsight labels, evaluated on an agent task and on LoCoMo: LRE (arXiv 2606.20954).
2. A separate non-LLM learned controller with Consolidate and Forget actions over a frozen LLM on ALFWorld-style tasks, trained from episode-end reward: MemCon (arXiv 2607.13591).
3. An exact ILP/MILP oracle for budgeted memory writing used as a certified upper bound: MemAudit (arXiv 2605.02199).
4. Failure attribution into irreversible (evicted) versus recoverable (retrieval miss) by restoring evidence: the restore-counterfactual audit (arXiv 2609.08279).
5. Budget sweeps against Random/Recency/salience heuristics with an oracle-retention bound: EMBER (arXiv 2606.05894).
6. Archive-with-index plus exact retrieval as the alternative to deletion on a memory-dependent ALFWorld variant: Memex(RL) (arXiv 2603.04257); hide/restore tools: Sculptor; soft offloading: ContextPilot.
7. DAgger imitation of a Belady oracle followed by RL refinement: Parrot (ICML 2020) and ForesightKV (ICML 2026); supervised learning on hindsight-scored memory demonstrations: Mem-T; reward-filtered SFT of a hindsight-best memory choice: provider-routing MemAgent.
8. Heuristic ranking instability across workloads: SOLAR (LRU/LFU lose to FIFO on semantic workloads) and Cacheus (workload primitives).
9. "Retrieved but not acted on" as a measured failure: MERIT (55% of correctly retrieved values acted on).
10. The endogenous-environment problem for memory credit ("memory turns the agent's past actions into part of its future environment"): Memory-R2.

**Likely distinctions (defensible, with the qualifier that no paper was found rather than that none exists).**
1. No paper trains a single separate policy over keep, evict, archive, retrieve, compact and consolidate jointly under one hard active budget with a frozen task model; each published system covers a subset.
2. No paper trains a sub-million-parameter neural controller (as opposed to a tabular bandit or logistic regression) with PPO for memory control.
3. No paper reports an attribution finer than three classes; the project's seven classes separate compression loss, consolidation error, archived-not-retrieved, retrieved-but-ignored and task-model reasoning.
4. No paper states or tests that imitating a hindsight deletion oracle is the wrong target once archival exists; the implication is scattered across Demand-MIN, MemAudit, Memex(RL) and MemAct.
5. No paper measures the hindsight oracle's undefinedness after trajectory divergence as a phenomenon; every caching paper assumes an exogenous stream and Memory-R2 names the problem without measuring it.
6. No paper compares against both an approximate and an exact ILP delete-only oracle on the same tasks while also running DAgger against that oracle.

**Unresolved novelty risks.**
1. LRE's revision of 3 September 2026 and MemCon's July 2026 version were the last fetched; either could add archive actions or an oracle in a later revision.
2. MemCon's early PDF extraction claimed an oracle comparison; the HTML extraction did not. If the body does contain an oracle, distinction 6 weakens.
3. "Beyond Memory Leaderboards: Budgeted Context Restoration" (arXiv 2607.16848) could not be extracted; it may contain a write/read decomposition overlapping the project's attribution.
4. MemTrace (arXiv 2605.28732, or 2606.17328 per the other note) may separate reasoning failure from memory failure, overlapping the `task_model_reasoning` class; undetermined from the abstract.
5. The Epistemics paper's ConsolidationBench is an oracle-by-construction benchmark for consolidation; if its oracle is Belady-like the project's oracle framing for CONSOLIDATE is anticipated.
6. TRACER's learned outcome model comparing chosen retention to full retention is a per-decision counterfactual credit close to the project's attribution for COMPACT; its per-tool granularity may be argued equivalent.
7. Hindsight Memory-PRM's delete-and-re-answer is a one-action-deviation roll-out; a reviewer may say per-failure attribution is the same construction relabelled.
8. The project's sequential result rests on a scripted environment; MemoryArena, Mem2ActBench, MERIT and MemGym exist and a reviewer will ask why none was run. Memex(RL) solved the closest published analogue by training the task model, so a "task-model-trained beats separate-controller" comparison is unrun.
9. Unfetched 2026 titles that could overlap: "Selective Forgetting: A Graph-Based Memory Framework" (arXiv 2608.28978), "Learning What to Remember: A Cognitively Grounded Multi-Factor Value Model" (arXiv 2606.12945), "What Training Data Teaches RL Memory Agents" (arXiv 2605.23067), MemOps (arXiv 2607.12893), DolphinBench (arXiv 2609.24971), StreamMemBench (arXiv 2606.14571), DynamicMem (arXiv 2606.22877), "Context Assembly as the Controlled Variable" (arXiv 2607.25408, thin extraction), TrustMem (arXiv 2606.25161), MemCoRe (arXiv 2602.07885).
10. The imitation-gap mapping (Proposition 1 applied to memory retention) is the researchers' inference; no paper states it for memory. It is safe to present as an explanation, not as prior work.
