# memctl: one-page research summary

*2026-09-30. Companion to `docs/research/HINDSIGHT_MEMORY_RESEARCH_NOTE.md`, which carries every source and caveat. All numbers come from run artifacts under `runs/` that are stamped `dirty: true` at commit `d215c8f`; they are indicative until rerun from a clean commit.*

**Problem.** A long-running agent's task model reads a bounded active context while observations, tool outputs and actions keep arriving. A controller must decide, before the need exists, what to keep, what to archive for later retrieval, what to delete, and what to compact or merge. Decisions compete for one budget and their cost arrives later, so this is sequential decision-making with delayed credit, not retrieval.

**Method.** `memctl` is a framework in which a *frozen* task model reads only the active tier and a swappable *controller* manages memory through eight operations (KEEP, EVICT, MOVE_TO_ARCHIVE, RETRIEVE_FROM_ARCHIVE, COMPACT, COMPACT_AND_ARCHIVE, CONSOLIDATE, NO_OP), any subset of which an experiment allows. Fourteen controllers share the interface: nine heuristics (FIFO, LRU, LFU, random, age-decay, similarity, salience, archive-everything, no-controller), an approximate Belady-style hindsight oracle and an exact integer-program oracle for the delete-only case, a prompted LLM, a JEV adapter (blocked: no key), and a 27k-parameter learned policy over 24 per-item features trained by DAgger imitation of the oracle and by PPO on task reward. Every failed query gets one of seven attribution labels (evicted, compression lost detail, consolidation incorrect, archived not retrieved, retrieved but ignored, task-model reasoning, invalid action), every controller runs the same seeded episodes, and every comparison is paired with a bootstrap interval and a minimum detectable effect. Environments: a synthetic recall task with exact ground truth, a sequential workflow task where a forgotten token forces a job restart (so the trajectory depends on memory), and LoCoMo / LongMemEval adapters (evidence retention only so far).

**Strongest result.** On the sequential workflow task at a 5 % budget, the imitation policy trained on that task completes every job (success 1.000, 1.2 restarts per episode, 240 training episodes) where FIFO completes 0.028 with 64 restarts, the best recall-task heuristic (salience) 0.001, and the hindsight oracle 0.808, because the oracle's reference pass no longer describes the episode after the first restart (`runs/exp5b_workflow_rl`). Supporting results: memory policy moves task success by up to 0.56 at equal budget (`exp1`); archive + BM25 retrieval lifts FIFO from 0.233 to 0.734 at 5 % and every remaining failure is a retrieval miss (`exp2`); the heuristic ranking flips between the two tasks (`exp5`); learned policies beat every recency rule by +0.24 to +0.49 and match the best content rule on the recall task (`exp4`).

**Strongest limitation.** Every number uses a perfect scripted task model, a lexical retriever, a free unlimited archive and hand-set synthetic generators whose query distribution matches the salience heuristic; the runs are stamped from a dirty working tree. The learned arm has not beaten the best task-specific heuristic on its own task (best case +0.018 at one budget), the delayed-reward hypothesis is unsupported (3 seeds within noise; 1 seed each on the workflow task), and the most informative negative result is that imitating the hindsight *deletion* expert is wrong once archiving is allowed: the imitator scores 0.521 at 5 % and fails by deleting, while a policy that archives everything and retrieves liberally scores 0.849 (`exp4b`). The JEV arm is blocked without an API key, and no language-model task model has run beyond an 11-query smoke test on a 4 GB GPU.

**Current thesis hypothesis (working).** Hindsight oracles are valuable teachers for memory controllers only when their action semantics match the learner's action set and information: with an archive, deletion labels must be replaced by archive-aware counterfactual regret, and after trajectory divergence the oracle must be recomputed. Under those conditions a small learned controller separate from a frozen task model can match the best task-specific heuristic on each task structure and, unlike any fixed rule, is not wrong on both. The literature search (2026-09-30) finds each component published in 2026 (LRE, MemCon, EMBER, MemAudit, Shen's restore-counterfactual audit, Parrot/ForesightKV) but no system combining a seven-action separate controller, hard budget, exact oracle, seven-way attribution and a trajectory-dependent task, and no paper stating the wrong-teacher effect for memory.

**Three next experiments.**
1. **Archive-aware regret labels.** Replace the deletion expert's labels with continuation-regret labels computed by the existing switch-to-oracle replay, so archiving is credited by retrieval probability; retrain on the Experiment 4b grid. Falsified if the imitator still trails the untrained-retrieval-head policy at 2–10 % or still fails by `evicted`.
2. **One controller across task generators, with a ceiling.** Train jointly on recall and workflow episodes, add a Bayes-informed reference that knows the generator's query probabilities to bound the closable oracle gap, and add an online heuristic mixture (LeCaR-style) as the strongest fixed baseline. Falsified if the joint policy trails the per-task best heuristic on either task beyond its minimum detectable effect.
3. **A language-model task model and a published trajectory-dependent benchmark.** Rerun Experiments 1–5 with the `llm` agent on a rented ≥ 12 GB GPU (attribution reports the reasoning share), then port the controller to MemGym or MemoryArena. Falsified if controller differences vanish under a real model or the sequential advantage does not reappear.
