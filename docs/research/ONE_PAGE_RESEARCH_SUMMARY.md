# memctl: one-page research summary

*2026-10-06. Companion to `docs/research/HINDSIGHT_MEMORY_RESEARCH_NOTE.md` (a 2026-09-30 snapshot with every source and caveat) and to `EXPERIMENTS.md`, which holds every current number. Provenance is clean: every run was reproduced from commit `ef57fc4` on 2026-10-05 (`dirty: false`; only 9 cells of Experiment 4b changed, conclusions unchanged), and every later experiment ran from a clean commit.*

**Problem.** A long-running agent's task model reads a bounded active context while observations, tool outputs and actions keep arriving. A controller must decide, before the need exists, what to keep, what to archive for later retrieval, what to delete, and what to compact or merge. Decisions compete for one budget and their cost arrives later, so this is sequential decision-making with delayed credit, not retrieval.

**Method.** `memctl` is a framework in which a *frozen* task model reads only the active tier and a swappable *controller* manages memory through eight operations, any subset of which an experiment allows. Controllers share one interface: nine heuristics, an approximate and an exact (delete-only) hindsight oracle, a prompted LLM, a JEV adapter (still blocked: no key), and a 27,526-parameter learned policy. The policy is trained by DAgger on a hindsight expert (the oracle's labels, or a **regret expert** that accepts every least-regret action), by **cost-sensitive imitation**, by PPO or by **GRPO**, on one task or **jointly** on several; a plug-in Bayes rule prices the archive. Every failed query gets one attribution label; every comparison is paired over the same seeds with a bootstrap interval. Task models: a scripted reader, and real LLMs through any OpenAI-compatible server (`qwen2.5:3b` locally, Qwen2.5-7B-Instruct on a rented GPU). Environments: a synthetic recall task, a sequential workflow task where forgetting forces restarts, and LoCoMo / LongMemEval adapters (evidence retention only).

**Strongest result.** With an archive, the teacher decides everything: the same learner imitating the regret expert scores 0.851 at a 2 % budget against 0.335 imitating the oracle expert, and beats every fixed rule at 2–10 % (+0.092 [0.076, 0.107] over the best at 2 %; D1, 3 seeds). One joint controller matches each specialist on both the recall and the workflow task, where every fixed rule fails on one of them (D2, D2b). With Qwen2.5-7B as the reader over 100 episodes every D-series result holds: regret over oracle teacher +0.51 at 2 %, the learned policy over the best rule (FIFO-archive) +0.09, and the oracle's small memory beats full context by +0.04–0.06 (Exp. 9). An oracle-imitation warm start halves what RL reaches (GRPO 0.451 against 0.70–0.72 from scratch); GRPO solves the workflow task on all 3 seeds where PPO fails on one.

**Strongest limitation.** The remaining gap to the oracle is retrieval: at 2 % the learned policy's failures are mostly `archived_not_retrieved` (~300 per seed against 72 for the oracle in Exp. 9) with a lexical top-k retriever. A priced archive is only partly solved: at price 0.2 every archiving controller, including the plug-in rule, loses to deleting (D5, D5c). The workflow task has run only with the scripted reader; no published long-horizon benchmark (MemoryArena, MemGym) has been run; the delayed-reward hypothesis (H2) is unsupported and its multi-seed test (D6) was never run; the JEV arm is blocked.

**Current thesis hypothesis (working).** Hindsight is a good teacher for a memory controller only in the right form: the oracle's argmin labels are wrong once an archive exists (D1), least-regret sets fix a free archive but not a priced one (D5), and what should be learned from hindsight is a calibrated expected regret used in a decision rule (D5b). Under that teacher a small controller separate from a frozen task model beats every fixed rule, serves both task structures where every fixed rule fails on one, and keeps its advantage with a real 7B reader.
